# 对标分析与规律提取助手

## 适用范围

处理飞书知识库中的内容素材和规律文档。`02_内容素材`、`03_内容规律`是知识库层级，不是本地文件夹；使用飞书文档/知识库能力读取和写入，不创建本地替代文档。

已有的标题规律、开头规律和正文结构规律适用于所有类型的笔记（A 类视频、B 类图文、C 类长文）。新增的两类规律分别只使用指定来源：视频脚本规律来自 A 类视频素材下“视频解析”中的脚本文本；图片规律来自 B 类图文素材下的笔记图片及其图片文字/图片分析。

## 任务入口（严格执行）

- **对标分析**：用户要求分析、拆解一条/一批对标，或 content-collector 在完整采集后调用时，执行 [对标分析完整流程](references/benchmark-analysis.md)。包括需求提取、形式分类、标题/整组图片/正文分析、事实核验、借鉴 critique、飞书原位保存及通过 audience-report 回写洞察。通用方法集中在此，平台和主题要求按账号引用；完整分析只保存在飞书。
- **规律提炼**：用户要求跨篇归纳或更新规律时，才执行下方汇总与五类规律文档流程，复用已保存的单篇分析。单篇任务不自动重建汇总或更新五份文档。
- **发布反馈**：接收 review 的实际封面与数据，按本账号使用记录流程更新。

content-collector 的采集与本 Skill 的分析连续衔接，原有“入库须完成分析”的要求保留；缺原始材料交采集补齐，已有材料缺分析由本 Skill 补齐。所有入口均保留用户已确认、待确认及已排除状态。分析交接须提供飞书原位链接、单图/整组章节、修订号或更新时间，以及完整的逐页任务、关系与数量。writer 写作前按 image-copy-writer 的前置门槛实际读取；已有分析缺项在原文补齐，不能由下游另写一份摘要替代。

## 首次跨篇规律提取流程

1. 读取 `03_内容规律/_规律提取汇总.md`；若不存在，先按项目结构创建或定位对应文档。
2. 读取 `02_内容素材`下的素材文档，排除搜索关键词、入库检查报告和其他以 `_` 开头的辅助文档。只有标题、来源链接和可读正文齐全的内容才作为有效素材；缺失字段写“未采集”。
3. 为每条素材按统一字段写入或更新汇总底稿：素材文件、标题、开头 1-3 句原文、图片正文、正文结构。
4. 素材含本地/嵌入图片时，严格按图片顺序读取全部图片文字，单独写入 `图片正文`；图片只有装饰时写“无可读文字”，无法读取时写明具体路径，不跳过、不推测。开头必须区分“笔记文字开头”和“首图/图片开头”，图片文字不得冒充笔记文字原文。
5. 视频素材额外读取其“视频解析”子文档中的文本；只把其中可读、实际存在的脚本作为视频脚本材料，不用笔记正文替代视频脚本。图文素材额外读取其“笔记图片”子文档中的全部图片，按顺序查看图片文字和已记录的图片分析；图片无法读取时记录具体路径，不跳过、不推测。
6. 基于汇总底稿及上述类型专属材料生成或更新五份规律文档：
   - `03_内容规律/标题规律.md`
   - `03_内容规律/开头规律.md`
   - `03_内容规律/正文结构规律.md`
   - `03_内容规律/视频脚本规律.md`
   - `03_内容规律/图片规律.md`

## 规律判定与文档格式

- 同一种做法至少出现在 2 条素材中，才能进入“候选规律”；只出现 1 次进入“单条观察”。不要把跨素材总结写成单条观察，也不要用单一元素替代完整做法组合。
- 五份规律文档必须使用完全一致的一级章节顺序，不得按文档类型自行增加、改名或调换一级章节：
  1. `文档说明`
  2. `当前材料`
  3. `候选规律`
  4. `单条观察`
  5. `待确认`
  6. `已删除`
- `文档说明`固定包含“来源范围、当前样本、使用边界”；`当前材料`按文档类型展示标题、原文开头、正文结构、可读视频脚本或图片整组信息。某项没有内容时明确写“无”，不得省略章节。
- 每条候选规律使用以下字段：规律名称、大白话解释、适合什么内容、不适合什么内容、不可照搬点、来源素材。来源必须写具体素材文件路径。
- 五份文档中的每条候选规律必须使用同一种呈现模板和字段顺序；推荐以两列表格呈现“字段 / 内容”，不得有的文档用连续段落、有的用列表、有的用不同字段名。
- 标题规律：先完整列出当前汇总底稿中的全部标题，再提取重复出现的元素组合；不得只统计孤立元素。
- 开头规律：保留 1-2 句来源原文作为示例，不改写；同时使用笔记正文开头和图片正文中的首图/前几张图片信息，但明确标注来源。
- 正文结构规律：按原文实际顺序写清结构链路和适合的内容类型；同时参考笔记正文与图片正文。
- 视频脚本规律：只分析 A 类视频“视频解析”中的脚本文本，按口播实际顺序记录开场、问题提出、解释/信息展开、转折、收束和结尾动作等；没有可读脚本文本的素材写“未采集”，不从视频标题或笔记正文推测。
- 图片规律：只分析 B 类图文的笔记图片，按图片顺序记录可见的信息组织、单张图承担的内容、图文关系和连续图片的编排方式；图片中的文字可作为证据，但不得把图片文字冒充笔记正文。图片只有装饰时写“无可读文字”，无法读取时写明具体路径。
- 图片规律中的“图片分析”必须区分已记录分析与待分析：素材表格标记为“未分析”时，只能保留该状态，不能把模型推测写成已确认规律。
- 类型专属材料只写分析结果，不写采集或整理过程。已经检测到视频脚本时，直接记录脚本结构、推进顺序和可确认的表达方式，不重复写“原始转写”“逐字稿”“二次校对稿”等来源过程描述；只有未检测到或尚未提供脚本时，才写“未检测到”“待添加”或“未采集”。
- 图片专属材料只写图片信息组织、单图作用、图片之间的关系及可确认的图片文字分析；不要把“图片已下载”“图片已读取”等过程状态写成分析内容。图片分析尚未完成时，保留“未分析”；无法读取时，才记录具体路径和“无法读取”。
- A 类每份“视频解析”子文档也必须使用统一一级章节顺序：`视频信息`、`封面图`、`内容结构分析`、`标题与开头`、`画面与复刻适配性`、`逐字稿`、`核查备注`。有封面资源时插入真实封面；没有时写明“未采集”，不能只留空标题。逐字稿保留素材中实际存在的原文，不以整理稿替换或补写。
- 改写内容必须单独标注“AI 示例”，不能冒充原笔记原文。
- 不写“这样一定会爆”“平台算法喜欢”等当前素材无法证明的因果结论。

## 对标分析与跨篇规律的衔接

单篇完整分析由本 Skill 按 [对标分析](references/benchmark-analysis.md) 原位维护在素材的飞书文档。跨篇提炼时核对原图、版本和完整性，完整则引用，缺项先执行单篇流程补齐。规律条目只保留具体引用、必要短摘及跨素材比较，不复制整份分析。

比较标题统领、文本块、图文关系和页面推进是否真正相同，不能仅因页数或模块数相同归为一条规律。至少两条独立素材才形成候选规律；单篇分析可直接用于该篇适配，不受两篇门槛限制。正文叙述、需求、总结作用与核验结论一并引用原分析。

## 封面专项提取

封面分析属于本Skill的明确职责。每次提取图片规律或收到封面复盘反馈，读取 [封面机制与数据反馈](references/cover-analysis.md)。在现有《图片规律》的当前材料、候选规律、单条观察中标记“封面”，在条目内部维护专项字段；沿用六个一级章节，不另建重复规律库，也不把内页分析充当封面分析。

## 增量更新流程

当用户说“我搜集了新内容，帮我更新内容规律”或同义请求时：

1. 先识别汇总底稿中已经存在的素材 ID、素材文件和已有规律。
2. 只整理新增有效素材；已有素材不重复录入。
3. 将新增素材与已有规律对比：满足至少 2 条素材的同一种做法时，追加来源或补强现有规律；已有规律已覆盖时，不重复新建同名规律。
4. 只出现 1 次的新做法放入“单条观察”或汇总底稿，不提前升级为候选规律。
5. 对五类规律都执行同样的跨素材门槛、状态保留和增量规则。保留用户已确认的规律和状态，不删除、不覆盖、不降级。若用户明确指定“本期可用 / 以后再试 / 已删除”，按指定状态更新；已删除规律移到文末“已删除”区域并保留删除原因。

## 本账号使用记录与验证反馈

更新规律时读取 review 交接的“规律反馈包”，按账号隔离，并在匹配的候选规律或单条观察内部增加“本账号使用记录”，不增加一级章节或改动统一章节顺序。

记录：规律 ID/名称、笔记与复盘链接、实际采用版本/位置、测试问题、比较对象、观察窗口与指标、用户评论、混杂因素、适用条件及下一步。保持“对标中出现的做法”和“本账号实际观察”分开；两条对标重复不能证明效果，本账号单篇好坏也不能证明因果。

证据状态可记为“未测试 / 已使用但证据不足 / 多篇观察支持 / 结果不一致”，并附具体来源，不自动改变用户确认的“本期可用 / 以后再试 / 已删除”。无匹配规律时放入单条观察或待确认，不虚构编号；不重新启用用户已删除的素材与规律。

收到已授权的反馈更新时直接整合到对应条目并回读；只有生成反馈包、尚未实际写回时不得声称规律库已更新。

## 写入与核对

使用 `lark-doc` 读取和编辑文档，使用 `lark-wiki` 定位知识库节点；遵循这两个 Skill 的身份、读取、写入和验证流程。单篇分析按对标分析验收回读；跨篇更新后重新读取本次实际修改的规律文档，核对素材数量、来源路径、候选/观察分区、待确认清单，以及用户已确认的规律是否仍然保留。

修改任意规律文档前，必须先通读当前可见全文，再按统一、结构化、易读的方式整体整理或重写；不得只在文末无序追加。不得依赖或提及用户当前不可见的历史版本，也不要使用“上一版文档”等表述。整体重写时，必须保留当前全文中仍然存在的有效信息；新增或修正内容应放入对应结构区域。
