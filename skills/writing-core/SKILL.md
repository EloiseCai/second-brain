# 通用写作要求

本包只维护通用规则；具体平台和主题要求由调用方另外引用。所有内容交付使用当前飞书创作文档。

## 写前资料与交付验收（独立于宿主项目文件）

所有写作和改稿先读取工作间配置绑定的定位总览、写作原则、平台规则及账号词库，交付前再对照复核。规则由本Skill、平台包与主题包直接提供；不以读取项目agents.md或维护者历史会话作为执行前提。用户已确认的资料链接优先于主题包内的历史入口，缺配置交workspace-initializer补齐。

来源保留具体文档链接、章节或文件路径，不只写“来自小红书”。不编造经历、需求、趋势、数据和效果。更新文档前通读当前全文，将新内容融入已有结构并保留有效信息；不无序追加、不擅自覆盖用户成稿，也不用用户不可见的历史版本解释当前内容。

交付检查所有读者可见文字：标题、正文、产品句、互动、Hashtag、封面、内页、口播和字幕。按当前账号绑定的词库及平台要求逐项检查；命中后结合整句自然改写，必要时用含义清楚的Emoji表达。账号专属的禁用措辞和导流限制读取主题包，不扩为所有账号的统一禁令。

## 写作提点：让痛点落到真实场景（严格执行）

2026-10-15用户确认：从调研、选题、Creative Brief，到标题、钩子、图片文字、正文、产品句与互动，凡采用痛点或场景均执行 [场景细节与证据性质](../research-core/references/scene-contract.md)。普通图文与知识型同样需要找到触发时刻、当时动作和遇到的阻碍；不强制所有内容写完整故事，也不要求每句话重复三项。

写前实际回读当前账号问题卡及来源，区分真实记录、明确标注的示例和待确认设想。示例可用于解释，不能证明真实用户需求或冒充本人经历；标注须随文字、图片或故事一起进入成品。缺失细节按协议补证或收窄，不以“可能、如果”等措辞伪装成已有痛点。

写作要让具体处境影响答案、例子、选择标准或操作顺序。原因解释须有依据，比喻帮助理解但不代替证明；方法写到可理解、可执行的程度，复杂问题可分阶段，不机械限定一个动作或固定段落数。产品仅在已启用且有功能依据时承接同一任务的实际障碍，不额外编出“坚持不了”等困难。

每次逐模块及全篇 critique，沿同一来源核对“场景细节→实际文案/画面→回答的障碍”。只有开头贴了场景词、主体仍未回答具体问题，或细节证据不足却按真实经历呈现，均不能放行。详细检查唯一维护在上述协议，不增设逐段人工审批。

## 表达与信息取舍

需求提取、选题交接、Brief 和各写作模块共同执行 [具体场景与对标角度保留](references/angle-fidelity.md)。这是通用要求；场景与对标分析仍保存于飞书原位置，下游引用，不另建副本。

- 表达清楚、逻辑顺畅，保留有用的具体例子、丰富用词、生活画面及长短句节奏。围绕同一主旨自然推进，说明做什么、怎么做、为什么和好处，可跨相邻段落讲完整，不固定每段句数或步骤数。用人能直接理解的对象和动作表达，减少抽象术语堆叠。
- 删除空话、重复、过程语句、避责套话；必要事实条件保留在具体答案旁，不把查证工作交给读者。
- 建议交代明确对象和动作，使读者知道如何照做。保留服务本篇的理由、例子和自然承接，避免“综合考虑、合理安排”等没有操作对象的句子。
- 信息量以解决已确认问题为准。只做本篇必要的信息提点与整合，不把查到的每个知识都塞入正文。图文正文与图片的分工按下节判断，不能以信息曾在图片出现为由直接删除。
- 用户处境、困扰、愿望和情绪以当前账号《用户洞察》中适用于本篇的有效条目为依据。写前定位问题ID、原始证据、适用人群与审核状态；用户洞察没有支持的情况，不写成读者处境，也不以“如果、可能、一时”等条件词包装成假设。用户本轮直接提供并明确要求采用的信息按原话处理，不替用户延伸。
- 对标作者概括、单条评论、搜索词、AI推断或待审核线索不能直接成为本篇用户情况。将评论或推断写回用户洞察，不等于它已经得到确认；不得以AI自己写入的条目或Brief代替证据与适用性核验。用户否定某情况适用于本篇时，以本次纠正为准，移除相应场景及推导建议，不拿来源中出现过该说法为继续使用辩护。没有有效困扰依据时，直接交付有依据的主题信息和可执行建议，不另造一个困境。
- 标签化表达按 `title-writer` 的人群标签规则执行；其他模块引用同一规则，不另存标签词表。

开头用文字交代适用于本篇的人群、处境和眼前选择，Emoji只增强表达，不独自承担关键语境。按对标的实际连续推进接住问题、及时回答，再用具体内容展开；不把某篇示例顺序固定用于所有题目。

## 每次写作与改稿重新对照原文

**每一轮都执行（2026-10-09用户确认）。** 初写、局部修改、整篇重写，以及收到用户反馈后的再次修改，都必须在落笔前重新读取当前模块已选的对标原文。此前读过、已有分析表、会话摘要或上一份AI稿，均不能替代本轮读取。正文改稿完整重读正文主对标；其他模块读取对应原文的完整阅读单元及必要上下文，不只摘一句。

1. 先分清用户要求改变的内容或重点，以及仍须保留的已认可表达；将修改意见带回原文，重新辨认语气与用词力度、长短句节奏、信息先后、段落承接和收尾方式，再决定怎样改。反馈不自动构成换掉写作风格或扩充说明篇幅的要求；用户明确要求换风格或结构时以其要求为准。
2. 同时校准内容和写法，不能只在现有稿件上补信息、换词或增段。局部修改仍限定在问题及受影响上下文，不借重新对标推翻已认可内容；全文重写重新组织行文，不沿用未经复核的旧稿骨架。
3. 写后将本轮实际改句与对标原文并排复读，再连读全文，检查语气、节奏、重点位置、信息密度和衔接是否仍成立。借鉴写作方式，不照搬独特措辞、个人经历或不适用的事实，不把本篇对标的格式固定成其他选题模板。
4. 在现有制作备注更新“本轮反馈 → 重新读取的原文链接与位置 → 实际借鉴的写法 → 改句及复查结论”。只有内容覆盖或来源映射、没有实际风格与行文核对，不能判为完成。无法取得完整原文时说明缺口，不声称已完成对标校准。

## 正文与图片的互补

**主题一致是互补的前提（2026-10-07用户确认）。** 正文须围绕本篇已确认主题及图片正在回答的问题展开，补充同一对象的选择理由、使用方法、必要条件或解释。不能为了与图片不同而另起相邻话题，也不能用产品的能力范围反过来扩大正文主线。事实正确、有营养价值或与账号相关，都不能替代与本篇主题直接相关。

正文可以引用、概括和强调图片中的事实、例子与结论，用来补充说明、连接信息、突出重要之处，帮助读者理解与行动，并吸引继续往下读。去重针对机械逐页照抄和没有新增阅读作用的复述，不要求正文与图片信息零重合，也不要求每句增加一个新知识点。

逐句辨认其作用：解释为什么、补必要条件、整合多页关系、给出使用方法、强调关键选择，或自然承接下文。保留发挥这些作用的句子；只有换词重复且不增加理解、记忆、行动或阅读牵引的才删改。阅读牵引来自具体问题、重要信息与自然推进，不靠空泛预告、虚构困扰或故意拖延答案。

写前用一句话对齐“图片讲什么、正文补什么”，写后逐段定位其补充的图片信息或核心问题。无法直接对应的独立展开应删去或收回主题；评论副问题及互动同样不能把主线带走。比如汤谱图片配喝汤主题正文，可补选汤、少油做法和吃汤料，不能展开成整餐菜单或其他菜肴的推荐。若搭配只是必要提醒，默认在产品承接前用一句话交代“还需搭配主食和蔬菜”等条件，不扩写餐次、菜品和营养分工；本篇主题本来就是整餐搭配或用户另有明确要求时，按该主题展开。此例说明边界，不要求所有文章加入搭配句。

## 逐句表达 critique（严格执行）

逐模块审查时必须覆盖该模块每一句实际读者文案，包含产品句、评论钩子及独立短句；不能只抽查段首、问题句或整段概括。按自然语义句审，分行不会自动变成多个句子。每句依次检查：

1. **清楚与价值**：对象、指代、关系是否明确；这句提供什么信息或阅读作用；是否废话、空泛或无意义重复。
2. **表达选择**：当前说法是否藏住重点；能否换成更直接的对象、动作、比较或例子，让重要信息更容易看见。已有清楚且获认可的句子保留，不为显示修改而换词。
3. **简洁有力**：是否能减少绕弯、过程语句、避责套话而保住知识、理由、条件、语气与节奏；不以最短字数为目标。
4. **理解与行动**：建议句是否让读者知道怎么做，是否还要猜对象、数量或步骤；解释、过渡和提问句检查是否帮助理解、推进阅读或清楚回答，不强制每句话都写成指令。结合相邻句确认动作与理由完整。

在同一飞书制作备注逐句记录：句子 ID 与当前原句 → 本句作用 → 四项检查的具体结论 → 保留/修改/合并/删除及实际改句 → 复查。记录须覆盖全文，可简写但不能漏句；读者正文不展示审校记录。每次修改后重读完整句子及相邻语境，继续检查四项，不能改一次就默认通过。模块逐句全部通过后再审模块关系，全篇完成后再审结构与承诺。

## 评论的固定用途

**采用门槛（用户已确认）：评论本身必须有可见的非零点赞，或至少一条可核验回复。** 保存原话、所属帖子和位置、采集时间，以及点赞数或实际回复上下文；原帖总点赞/评论数不能替代这条评论自己的互动。零点赞且无回复、只有点赞按钮、互动不可见的评论均不能作为已采用的评论证据。缺少合格评论时继续补查；确实无法访问则明确缺口，不编造、不降低门槛，也不把该模块判为完成。后续写作核验沿用这份证据，不重复采集。


写作前完整读取与本题直接相关的高互动对标，主线从对标内容展开、信息顺序、例子和呈现手法中提炼。每篇至少保留1条符合上述互动门槛且可追溯的相关评论及来源；同一评论不重复作为多篇的新采用素材，同一困境不拆成多个近义观点，已有稿的改稿沿用原证据不算重复采用。已明确采用评论中的困境时忠实回应，不把“想吃辣”改成“吃多怕胖”；选中的副问题放在合适位置自然回答，逐段核对核心承诺。

选题已确认后的评论材料，用于正文与图片的挂件词、表达、补充角度和互动设计，不决定或改写选题、核心承诺与全文主线。选题发现阶段如何研究问题仍归 `topic-generator` / `audience-report`，不能混用两个阶段的权限。

评论有点赞或回复仅说明满足采集门槛，不表示可以直接套作本篇目标用户的处境。涉及用户情况时仍执行上文《用户洞察》的来源、状态与适用性检查；不符合则只保留为研究材料，不强行在正文安排对应困扰或建议。

每条采用的评论记录：原话与具体来源 → 原帖提问及前后语境 → 用户实际回答了什么 → 为什么愿意说（有原话证据或编辑推断分别标明）→ 可借鉴的用词/角度 → 本篇落点。不能凭一句评论补造完整经历或普遍需求。

文末提问从期望得到的回答类型倒推：分享自己的做法、说出具体选择、补充替代方案或提出仍未解决的问题。先看真实评论属于哪种回答，再设计与本篇直接相关、容易作答的一句问话；原帖未明确提问时如实记录，不能编造它的问题。预计回答只作设计依据，不写成真实用户反馈、不保证会激发互动；避免泛泛“你怎么看”、多题连问、暗示标准答案或逼读者承认某种困扰。原评论只存一次，以证据 ID 引用到不同分析位置，不重复充当多个独立证据。

## 逐模块 critique 与放行（严格执行）

模块按实际内容划分：每条标题、每页图片及实质文本块、正文开头/各段落模块/产品承接/文末提问/标签；不强定模块数。每个模块写完立即审，修改复查通过后才编写下一模块；最后再审整篇衔接、重复与承诺覆盖。

每项检查都必须指向实际原句与来源，至少核对：
1. 任务：本模块回答什么，实际交付的答案在哪里；有没有偏离已确认题意。
2. 证据：场景、情绪、标签、知识、功能和评论用途是否有相应依据；推断有无伪装成事实。
3. 可用性：读者知道如何操作吗；有没有只说概念、让读者再猜再查的句子。
4. 信息分工：相对前文和图片增加什么理解、记忆、选择或行动价值；能无损删除的废话是否清除。
5. 表达：过程语句、避责语句、过多信息、绕弯、账号禁用表达是否已处理。
6. 三部分要求：通用、平台、主题的实际适用条目是否都落实；未读取不能写通过。

在同一飞书制作备注保存一张当前模块表：模块位置/实际原句 → 适用要求与来源 → 发现的问题 → 已改原句 → 复查结论。无问题也要写具体依据，不能只打勾。通过、退回修改、待核验分开；缺证据不能按通过放行。用户审批另按 Brief 规则执行，内部 critique 不增加逐段人工审批。

发现上述任一未解决问题就留在当前模块修复；无可用来源时收窄表述、改成有依据的动作或报告确切缺口。修改一个模块后重审受影响模块及全篇关系，不能只复查换过的词。重复错误须修正对应放行条件并重查同类位置，不能用道歉代替完成修复。
