# 社媒来源与平台适配协议 v0.2

2026-10-12 用户明确调整：雷达以社媒内容与讨论为主。通用底座维护本协议，各账号只保存自己的平台、博主、种子词和运行状态。以下为采集策略，实际工具能力与登录每次验证，不宣称已经实现所有平台的自动抓取。

## 配置与调度

`radar_mode` 沿用 router 开关。`radar_sources` 独立于 `selected_platforms`，保存：

```json
{
  "mode": "social_content",
  "platforms": ["xiaohongshu", "x", "wechat", "douyin"],
  "forms": {"wechat": ["long_article", "image_post"]},
  "watch_accounts": {},
  "seed_terms": [],
  "exclude_terms": [],
  "fact_check_role": "supporting_only"
}
```

数组仅演示可配置结构，不是所有账号的默认平台或强制数量。博主使用平台+稳定ID/主页URL定位，显示名不能作为唯一ID。保留既有对标清单；候选博主与已选固定监控对象分开。检索词为空时读取当前主题包与洞察词表，模型扩词标检索假设。数量、频次和筛选阈值沿用用户已确认配置；不另设每平台配额。定时运行需单独配置，启用雷达不等于创建周期任务。

router 将来源配置、主题引用、窗口、已有实践来源、报告及各平台断点交给雷达。雷达逐平台读取适配策略，先固定博主、再关键词/话题发现，合并去重、交叉实践、critique、回写同一报告。用户限定本次平台时覆盖本轮范围，不改其他账号设置。来源平台的采集能力不要求该平台已有内容制作分支。

## 平台适配策略

网页路线与故障恢复统一引用 [research-core 浏览器入口](../../research-core/references/browser-route.md)。已配置API/连接器可作为采集适配器，但先检查工具实际支持的操作、当前授权和返回字段；不猜接口、不把自有账号管理权限当全站搜索能力。新连接器与浏览器登录态互不通用；切换仍按已授权工具路线执行。

| 平台 | 内容发现入口 | 原文采集与必要差异 | 当前能力如何判断 |
| --- | --- | --- | --- |
| 小红书 | 博主主页近期笔记；站内关键词/话题搜索；实际可见排序/联想词 | 图文保留作者正文和整组原图顺序；视频区分发布正文、逐字稿和画面。记录赞、藏、评论各原名；评论取可见原话及所属帖 | 分别验证搜索、正文、整组图片、视频/转写、评论，不用“已登录”代替全部成功 |
| X | 已选账号主页；站内搜索/话题/回复；或实际可用的授权搜索接口 | 区分原帖、thread、回复、引用与转帖；保留上下文和原作者。可见浏览/点赞/回复/转帖分别登记；thread未展开不能称全文 | 网页或API逐项验证；未取得某指标写未知，不能用缺失字段算0 |
| 微信公众号 | 已选账号文章列表/用户提供链接；当前授权环境内可用的公众号搜索；搜索引擎只作原文入口发现 | 同一平台分 long_article / image_post。长文读可见正文及文内配图；贴图读完整组图及配文。阅读、在看、点赞、留言可能不可见，按实际记录 | 记录能否搜账号、搜内容、读原文/整组图/可见留言。只有链接入口时标 link_only，不称全平台搜索或完整监控 |
| 抖音 | 已选账号主页；站内关键词/话题搜索及实际可见榜单；或已验证授权接口 | 保留视频标题/发布正文、时长、字幕/音频逐字稿、关键画面与评论。图文作品保留整组图。机器转写标来源和未校对处 | 元数据、视频可播放、转写、画面、评论分别登记；播放成功不等于读完内容 |
| 视频号（账号自行选用） | 实际可用的微信/视频号入口、已选账号或用户链接 | 视频材料规则同上，记录实际可见指标；不把公众号正文或抖音搬运替代为视频号原文 | 未接通客户端/工具时记 unavailable 或 needs_login，不能凭浏览器能力声称支持站内全量搜索 |

增加平台时沿用同一接口，填写发现入口、各形式取证方法、指标、授权及限制；不复制通用流程。一个平台不可用时继续其他已选平台，整体部分完成；不静默换工具或用新闻站填补。

## 统一记录与恢复接口

每个平台保存非敏感 `platform_state`：`platform`、`adapter`、工具版本及实际profile/session、`status`、`capabilities`、最近成功URL/读取范围/时间、错误、下一动作。状态按实际使用 `not_checked / ready / partial / needs_login / unavailable`；搜索、正文、图片、视频转写、画面、评论分别说明是否验证。恢复已有成功路线，凭据不入配置。

每条采集记录包含：

- `source_id`、平台、账号ID/主页、作者、原帖ID及规范URL、形式、发表日期/日期精度、采集时间。
- 实际命中词、发现路径、排序、使用适配器；正文/图片/视频/评论读取范围及原始证据位置。
- `metrics`：指标原名、值、是否可见、采集时间；保留“1.2万”等页面原值，解析数值注明换算。不可见用null，不能填0。
- 评论/追问保留原话和所属原帖；作者内容推断与读者真实表达分开。视频字幕/ASR与人工逐字稿分别注明来源。
- `capture_status` 与 `analysis_status` 分开；雷达候选摘要不算完整素材，不自动增加10条素材门计数。被正式采用时交content-collector按形式完整采集入库。

原帖ID/规范URL先去重；转载、搬运、同人跨平台内容归为同源并保留各平台指标。仅主题相似不能合并为同一原始内容。话题聚合保留代表原文和独立作者数，指标只在相同平台/指标/可比窗口内解释；无多次快照不称涨幅，无平台热度依据不称热门。

## 实践交叉与报告验收

候选按具体读者问题、可见社媒讨论证据、本人实践支撑、新增知识或可照做的产物、时效筛选。只有热度但无实践支撑的标补实践；有真实成果而无当前热点的标常青。不要用产品公告来证明读者需要，不把内部改动日志包装为痛点。

报告先给：当前可选社媒话题及实践交叉结论；再给待核验/常青；最后给渠道覆盖、原始来源、事实核验背景与检索记录。每条有原文、时间、可见互动、问题关联、实践来源/完成层级、读者增量、缺口和建议下一步。官方资料放事实核验背景，不进入社媒热点榜。既有报告若混入官方新闻，保留其有效核验信息并移至背景，纠正当前话题状态。

验收分别报告：规则已部署、平台已接通、扫描已执行、正式素材已入档、周期任务已启用。不得相互替代；没有可用社媒原文时可以交付覆盖报告，但有效社媒话题为0，下一步明确到平台/故障层。
