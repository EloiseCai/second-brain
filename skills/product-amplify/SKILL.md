# 产品力增强

让读者通过与本篇有关的实际功能和证据理解产品价值。产出可使用的图片与文案，积累可复用的图卡，不能只建议“加一栏产品介绍”。

## 入口与衔接

- 是否启用按内容包逐篇记录 product_mode=off/on/pending，结合用户意图与本题适配判断；用户已确定的选择直接沿用，未定在策划确认时一并提出，不把每篇都默认开启。off跳过本模块，不能因无产品承接判正文不完整。
- on时，本模块负责产品文案与产品图；body-writer负责其余正文和整篇衔接，不重复写另一套产品段。
- 图文：制作一张与本题相关的产品承接图，正文承接写清本题真实用途；搜索指引仅按当前用户授权和账号最新用词/渠道限制处理，确切产品名称、搜索入口及能力按主题资料核验。妈妈善食必须读取 pregnabite-writing 的产品承接用词要求，旧示例不覆盖最新限制，不默认追加联系方式、链接或二维码，也不声称平台保证允许。
- 公众号：文末加入简洁产品承接话术，说明产品怎样继续帮助当前问题；本模式不默认额外生成产品图片，用户另有要求时制作。
- 漫画故事：产品开启时与story-builder同一节点联合写作，落笔前匹配困境、功能、真实使用动作与结果，首稿即包含实际产品文字。内部可往返整合，对用户交付一份完整故事；不能把读完功能表或另留产品段视为完成。执行[联合首稿与节奏协议](../story-builder/references/story-arc-and-density.md)。
- 图文/公众号可按其既有流程在主体后制作承接；漫画的产品匹配发生于故事首稿之前，并随全文一起复核，不能移到首次故事交付之后。已批准说法和图片审批继续保留。
- 图库建设仍可独立执行；封面等既有选择点不代用户决定。
- 从当前创作文档父链或用户明确给定的账号节点确定 `account_root`，在其子树先读取定位总览、产品说明和已确认写作偏好。旧路径 `00_个人背景/定位总览_v0.1.md` 不存在时沿当前账号目录定位，不能跨账号取同名文件。账号无法确定时只询问必要的节点/文档链接；通用流程设计可先完成，不声称读过定位。
- 飞书正文操作使用 `lark-doc`，知识库节点使用 `lark-wiki`，上传归档使用 `lark-drive`，执行时读取对应 skill。来源保存完整作用域路径、URL/token，截图另记本地绝对路径。只修改当前任务相关文档和资产。

## 1. 建立产品证据

先读取主题包绑定的产品资料目录，再按本题分别读取功能事实、产品承接文案规律、相关图库及其制作依据、适用的真实使用记录。已有输入可引用读取位置与版本；没有实际读到不能写“已执行”。功能事实说明能做什么，承接规律说明怎样表达，图库说明怎样展示，使用记录说明谁实际做过什么，四者不能互相充当证明。摘要未覆盖的能力先沿目录和引用查找，再报告具体缺口，不立即让用户重复提供。

先读取当前主题包绑定的 `product_facts` 飞书/已确认后端文档，取得最新功能状态、范围与证据；妈妈善食按 [产品事实入口](references/mama-shanshi.md) 定位企业飞书。通用Skill内置方法，不内置持续变化的账号功能清单。再读取文档关联的真实页面和共享截图，按 [交付与资产记录](references/deliverables.md) 维护证据卡。新主题缺入口时先定位或建立其功能文档；权限失败不回退维护者电脑、其他账号资料或会话记忆。

功能匹配与交付前均读取当前产品事实，内容包登记功能ID、当前状态、采用说法及读取日期/修订号；变更后只使用当前有效范围。共享截图和必要证据须有可访问的飞书链接，本地绝对路径仅用于制作和归档，不作为另一位使用者获取功能事实的唯一方式。

区分用户已确认功能、实际查看的产品证据和尚待核验的推测。宣传语不能超过证据范围。技术优化要转为读者能理解且能证明的用途；“做了 RAG”不能证明推荐准确、专业认证或健康效果。单个带引用结果不能证明全部结果均有引用，食谱样本也不能证明长期不重复。

建立信任优先展示实际操作、输出和可核查依据。引用权威资料不等于获得机构背书，不暗示合作、认证或专家推荐。涉及健康结论时另查当前权威原文，不能因产品引用了某来源就认为结论已证实。资料仅支持一般原则时，不把生成的整道食谱称为机构原版食谱。

## 2. 按本篇问题匹配图卡

故事方法与产品增益按[方案先于产品呈现](../story-builder/references/story-development.md)分别交接：方法本身可执行；产品以已确认能力提高执行效率或提供具体帮助，不要求它独占整个解决方案。写清辅助动作或输出如何帮助人物下一步，不能只有“更方便、更高效”，也不强造非用产品不可的障碍。检查实际动作顺序，避免人物已选择并准备完，产品才出场替她选择。第一稿含产品的要求不等于第一稿把全部方案归功于产品。

漫画故事的桥梁由本模块与story-builder实际设计：具体困境→独立可执行的方案（对象、标准、例子、做法）→其中需要辅助的环节→已确认功能→具体辅助动作与帮助。至少比较最相关方案与一个可能错配的方案，说明取舍后写入完整故事，不要求用户提供已经写好的承接。功能证据与真人使用证据分开；缺后者仍完成明确标注的设计提案，见[研究后的执行方法](../story-builder/references/story-method-research.md)。用户要求真实使用时，提案不自动升级为真人见证或发布批准。

故事承接执行[两种形式](../story-builder/references/story-development.md#产品故事的两种承接2026-10-16用户确认)：优先以第一人称写“困境—用产品完成的具体动作—直接帮助”；关联不足时，先给对应困境的简单方案，再轻量分享工具。先研究针对困境的具体解决方案，再匹配能力；产品匹配可提前参与构思，正文仍先讲清方案，再引出工具辅助。遮住产品段仍要知道怎么做，不能用“看推荐”替代方案；不能用泛泛三餐安排代替夜间加餐这类具体问题。核对真实使用或明确示例身份，不把第一人称默认改成第三人称建议。

按 [场景协议](../research-core/references/scene-contract.md) 将“触发时刻、当时动作、具体阻碍→产品帮助的动作→功能证据”连起来。方法后的剩余障碍仍需依据，不能默认所有读者都找不到素材或坚持不了，也不能为推出产品放大焦虑。产品演示明确标为示例，不能把功能可用写成作者已使用并获得某种结果；无适配能力时按本篇开关及缺口处理。

先读取选题/初稿中的主要内容任务、提前记录的产品适配判断与待验证问题，再核对当前功能证据。提取初稿已有的人群、场景、下一步动作及真实问题来源。用“本篇问题 → 相关功能 → 可见证据 → 可用文案 → 放置位置”选择图卡，说明取舍。

- 默认选一个最相关主卖点，有明确作用时补一个信任或执行图；按信息量调整，不硬塞全部功能。
- 先回答笔记本身的问题，再在需要继续操作的位置引出产品。图卡展示有用的产品内容，不能只有手机外框、品牌口号和功能名。
- 食谱规划类笔记也可选“问题式结尾行动图”：用一个具体问题引出单一行动，再以餐食或食谱预览说明读者能获得什么。参考图库 PA006 的版式逻辑；按本篇场景改文案和示例，不把某张图的标题或搜索语固定套用到所有笔记。它是内容预览形式，不应被当作真实产品界面或功能效果证明。
- 查找同账号、同功能且适用于当前界面的资产。复用真实截图和视觉组件，按本篇改标题、标注、场景；弱关联时不加入该卖点。
- 没有证据的受众痛点标为创作假设，不能写成“妈妈们都担心”。没有适配功能时提出关闭本篇承接或核实能力，不强造关联。

## 3. 制作截图宣传图

有可访问产品入口时，用可用浏览器工具读取真实页面并截图，按对应工具和 skill 要求操作。先查现有截图和资料；缺少入口或登录时一次说明具体缺口，同时完成可独立推进的选图、文案和构图。不得将缺图方案称为成品。演示操作优先使用获授权的演示账号，不为截图改动真实食物或补剂记录。

每张图围绕一个主要价值组织：与本篇有关的一句话标题、清晰的真实页面局部、少量指向性标注、必要操作说明。根据界面和笔记决定布局，不要求产品图机械套食物清单对标版式。延续已选封面的颜色、字体和节奏；原有笔记图的其他要求仍遵守。

先选最有证明力的真实状态再截图，例如推荐及对应引用、几个可辨识食谱选项、实际打卡状态。不得假设产品有某个按钮或字段。标注只解释可见或其他证据明确支持的功能。记录裁切范围，不裁掉理解功能和引用所必需的上下文。

真实 UI 不由生成模型重画或补造。可用代码排版原始截图、标题和标注；需要 AI 位图装饰或图片编辑时读取并使用 `imagegen`，生成视觉与真实截图分开保存。合成后对照原截图，确保 UI 文字、数字、引用和状态未失真。无真实界面时只交付明确标识的结构草图，不冒充产品截图。

截图不包含他人身份或健康记录；示例数据标记演示。机构标志不作背书装饰，不虚构评价、使用量、对比结果或效果数据。

用户要求成图且素材充分时实际制作并展示，不停在提示词。缺少已定视觉方向时先完成一张主图供用户调整，其余图证据与文案可继续准备；有已选风格或已授权自主制作整组时直接完成，不增设固定审批。

## 4. 同步与归档

通读目标文档当前可见全文后再修改。保留有效素材包、来源和用户最终稿；在唯一 AI 初稿内同步图序、产品承接句、图片文案，制作证据独立记录，不在文末堆多个平行版本。用户最终稿默认只给建议，明确授权后才改原文。

遵守本账号当前内容边界。若不允许面向读者展示机构名称，使用符合边界的真实功能证明，完整文献留在制作备注；不能用机构背书替代，也不能裁切得让人误解证据。

本篇成图归档到当前账号 `05_内容草稿/` 下与创作文档同编号、同选题的图片文件夹。复用图库放在本账号该目录下的 `产品宣传图库` 节点/文件夹，已有位置时沿用；飞书知识文档不擅自改成本地替代件。本地制作文件与飞书资产建立路径映射。保存原截图、成图与编辑源文件，记录场景、证据范围、获取日期及版本/失效条件。复用前检查关键界面，失效图标为待更新，不删除历史资产。

## 交付检查

- 向策划/story-builder/writer实际交接“本稿开关、困境、对应功能、具体动作、直接帮助、承接形式、实际产品原句、位置、来源与状态”；采用第一人称时另标叙述者及真实使用依据。仅提供功能清单或建议“加产品”不算模块完成。

- 图卡回答本篇一个实际问题，让人看懂具体用途；证据支持标题，不把特色说成未经证明的独家优势。
- 逐张打开实际成图检查中文、指示线、裁切、引用、隐私和手机阅读大小；延续原笔记比例，无既定规格时按当前平台/载体确定，公众号不默认3:4，检查实际像素比例，不能只验提示词。
- 图序、正文和产品承接一致，保留已有互动句与标签，来源与制作说明不混进读者文案。
- 交付增强内容、实际图片预览/链接、采用与舍弃的卖点及必要缺口；区分成图、待截图方案、未核验说法。
- 向 review 交接图卡 ID/版本、实际使用位置、主张及想观察的用户疑虑。功能咨询可作为产品兴趣信号，不能当成使用、注册或付费；产品侧数据只能在授权且归因可核实时关联笔记，否则记为同期观察。
- 复盘只记录用户提供或实际读取的数据，可回写对应图卡的使用记录；保留观察窗口、证据链接及局限，不预言转化效果，不自动发布。记录复用/新制、制作耗时与返工原因，未知不估填。
- 当用户反馈某种产品图流量更好时，先记录为使用观察；复盘应区分笔记曝光、末页触达、行动点击与实际使用，并核对选题、封面、发布时间等差异。没有可比数据时只提出设计假设，不把流量差异归因为图卡形式。
