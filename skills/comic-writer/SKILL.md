# 漫画制作

由 [writing-router](../writing-router/SKILL.md) 统一进入，复用初始化、研究及主题补充协议。本Skill负责漫画制作串联、专属交接与进度，不替代各底座的实际执行。当前为试行分支，规则部署不等于实稿跑通。

## 每轮恢复与展示

读取[固定漫画全流程及状态协议](references/workflow.md)，恢复当前任务的逐节点记录。每轮漫画制作、修改、细调或进度答复，都从①正式写作开始展示同一张完整图；初始化在图外说明，保留节点ID、主线和范围，仅更新状态与当前位置；不以本轮改动的局部图或故事情节图代替。规则细调与本稿完成度分别报告。

恢复账号、平台、主题包、现行写作原则、独立漫画Brief、来源、审批和已有素材。不能把某页完成倒推为前序步骤完成；复用有证据的产物，从最早缺失的必需交接继续。仅做规则细调时不自动生成图片。

## 底座与逐节点交接

实际写作顺序固定为：已有任务目标与真实素材、3篇漫画故事对标采集分析 → story-builder＋product-amplify联合完整故事（首稿含产品） → 漫画对标适配与完整Brief → 分镜和短框文案。账号、主题、产品开关等已有输入由入口恢复，不以完成漫画Brief或先写钩子作为整体故事的前置条件。已有对标库和选题研究仍可复用；具体漫画表达在故事成立后确定。

执行[主题补充协议](../writing-router/references/topic-overlay.md)：通用方法在底座，账号资源和专属要求在主题包，某篇的选择在该篇Brief。每个节点读取相应补充资料并保存实际输出，不能用“已读Skill”标完成。

| 节点 | 底座与实质输出 |
| --- | --- |
| ① 洞察取材与选题研究 | research-core、audience-report、topic-generator及研究主题包；取材保留触发时刻、动作、阻碍和来源。topic-generator按漫画类型与本题共同匹配同一组至少3篇对标（本轮至少1篇新增），自行完整阅读、拆解和交接；content-collector定向采集，此路径不调用pattern-extractor。 |
| ② 整体产品故事首稿 | story-builder＋product-amplify联合执行[主线、节奏与信息预算](../story-builder/references/story-arc-and-density.md)。先匹配真实困境与产品行动，再写起承转合，第一稿包含实际产品承接与可证实的帮助。关闭产品时仅story-builder。不能将纯经历初稿标完成。 |
| ③ 漫画对标适配 | comic-writer复用①同一组对标、原图与拆解，将②故事落实为漫画表达方向；不默认重新搜索、不另计3篇。原始材料缺失定向调用content-collector，确需独立深入分析时才调用pattern-extractor，不重复已完成研究。 |
| ④ 漫画改编策划 | content-planner、hook-generator以联合故事为输入形成独立Brief、开场钩子和逐页信息预算，不先套页格倒推故事。 |
| ⑤ 全量分镜与文案 | content-writer调用image-copy-writer及适用title-writer；逐页逐格画面、全部短框文字、转场、事实与对标映射、产品落点。提纲或首页不能代替整组文案。 |
| ⑥ 文案复核与放行 | writing-core、平台包、主题包及content-writer现有复核与审批；核对连贯、产品匹配、事实及图文分工，不新增审批轮次。 |
| ⑦ 人物、画风与首页样张 | image-generator按适用工具协议制作P01；首页本身即封面。已有批准样张可复用，仍核查是否符合新分镜。 |
| ⑧ 后续图片与逐页验收 | image-generator；只生成已放行范围，实图检查人物、场景、动作、文字与跨页连续性。 |
| ⑨ 发布配套 | title-writer、body-writer及平台适用的hashtag-writer、pinned-comment-writer；漫画配文不冒充独立长文，产品说法沿用②。 |
| ⑩ 整包交付 | content-writer整篇验收与图片归档、回写绑定后端；核对最终文案与实际图片一致，交付和发布分别记录。 |
| ⑪ 发布后复盘 | review；用实际发布数据复盘，回流洞察与规律；无数据保持待执行。 |

①执行[第二轮研究](../topic-generator/references/second-round.md)，类型和主题共同筛选同一组对标，由topic-generator承担实质拆解。②写故事前读取①的研究结果，③再复用它做漫画表达适配。缺少①证据就退回①补查，不能以已有故事或规则文档倒推调研完成。

## 漫画专属执行

真实困扰改编与评论原话统一执行[story-builder对应规则](../story-builder/SKILL.md#真实困扰改编与评论原话2026-10-18用户确认)。①保留评论的完整原句与上下文；②在已授权创作模式下可合并多人真实困扰形成一个主角；⑤主动挑选适合剧情的原话作为对白、内心话或旁白，再按短框容量独立编排，不必全部换成AI概括。④Brief明确叙述模式，⑤记录逐句来源与引用/改编方式，⑥核对原意、条件、上下文及图文分工。不同来源可以服务同一创作主角；下文真人见证的使用记录要求不用于否决这种创作，也不把创作升级为真人亲历。

②完整故事与⑤漫画文字为两份不同职责的产物。完整故事允许充分、详细展开；⑤必须独立改编并逐句审查漫画对标，执行[分别写作与交接标准](../story-builder/references/comic-storyboard.md#完整故事与漫画文案分别写作2026-10-16用户确认)。仅把故事分句拆框、统计字数或完成试排，不标⑤完成；⑥检查实际改编及逐句证据，缺项退回⑤。

②分别检查独立成立的方法与产品提供的具体辅助，按[故事展开协议](../story-builder/references/story-development.md)执行；③优先寻找与主线相符的自然反转，有合适生活反差时尝试搞笑反转。④—⑥把[动作与文本分工](../story-builder/references/comic-storyboard.md)落实到逐页预算、全量分镜和复核，⑧对实际成图复查；不能以短框已经拆开代替图文分工。规则不新增节点或审批。

叙事采用[故事展开方法](../story-builder/references/story-development.md)；分镜、首页、人物状态、短框节奏及画面核验统一引用[漫画分镜协议](../story-builder/references/comic-storyboard.md)，不复制另一套规格。

首页让读者识别人群、当前处境与钩子，文字和画面共同建立场景，信息足够即止。按语义拆成独立短框，不把长句塞进一个大框，不靠缩字容纳多段信息。用户删除的额外句子与制作说明按本稿记录处理。孕期人物、配色、已批准文字由主题包与稿件提供，不硬编码为所有账号模板。

产品承接允许“有真实使用依据的第一人称困境—使用—帮助”，也允许简单方案后轻推荐工具，由真实功能与使用记录决定。优先查已绑定产品知识库，不重新询问已有信息。不同人的经历与使用记录不拼为同一人的亲历；未匹配清楚则记具体缺口，不能用泛化产品句宣称完成。不新增臆造的Forbidden清单。缺少真实使用记录时，仍由story-builder＋product-amplify完成明确标注的整篇承接设计供评审；将设计完成与真实见证可发布分开记录，不把“请用户提供产品如何解决问题”当下一步。故事方法研究读取[十份资料比较](../story-builder/references/story-method-research.md)，具体页框容量在④按本篇对标试排。

## 放行与状态

图片文案、正文、提示词继续执行[现有三轮复核](../content-writer/references/three-pass-review.md)，完整文本与已批准范围先于对应成图。记录产物、来源、复核结果及下一步；复用不等于重跑，阅读不等于产出，局部批准不等于全篇批准。

依状态协议分开维护规则细调与单稿执行。规则变动影响已有产物时标受影响项待复查；无关成果保留。本Skill不改变已有审批，不固定页数或字数，不自动发布。
