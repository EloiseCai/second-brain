# 发布正文写作

输入按平台区分：小红书图文使用获批标题、实际图片与已审文字、Creative Brief、研究成果、评论、关键词及产品原句；公众号使用正文创作 Brief、公众号正文主对标与分析、研究成果、评论、关键词及产品依据，先写完整正文，无需实际图片或图片文案批准。公众号执行 `../wechat-writer/SKILL.md` 的 WX4，写后再到 WX5 规划配图。局部修稿遵守用户指定范围。

正文初写及改稿必须执行 [至少三轮复核](../content-writer/references/three-pass-review.md)，每轮都完整核对本模块的逐句对标与主线、事实及推理、全文逐句表达与读者行动等全部适用要求；完成修正复查再交接，不能只审开头或用一轮整体自检替代。

## 三部分组合

必读 `../writing-core/SKILL.md`；小红书读 `../xiaohongshu-writing/SKILL.md`，公众号读 `../wechat-writer/SKILL.md`；妈妈善食读 `../pregnabite-writing/SKILL.md`。其他账号替换主题包及其真实来源。每部分可包含写法，按真实存在的适用条目组合，不复制到本文件。

## 正文钩子调用（严格执行）

每次正文初写或改稿前，读取 `../hook-generator/SKILL.md` 及其 [钩子原话与规律协议](../hook-generator/references/hook-library.md)，实际读取内容包本分支的钩子方案，并回到主题包 `hook_library` 中所选条目的正文原话、图片作用及整篇配合关系。已有方案沿用并核对；缺少方案、仅有标题钩子或场景/承诺发生变化时，先调用 hook-generator 补齐或校准，写入内容包并回读后再写正文。

按本篇实际内容落实开头、中段与结尾的吸引点，记录“参考原话及位置 → 本篇对应句/段 → 读者继续看的理由 → 实际交付的信息”。可以用具体场景、新发现、口感、操作便利或变化等形成阅读动力，不强制每段设悬念，不用反复抄标题代替正文钩子，也不为钩子改掉已确认的对标结构和主旨。调用方法统一引用上述协议，不另建一套规则。

逐模块 critique 时核对钩子是否实际进入正文、吸引力是否被改成空话、期待是否及时兑现，以及与标题和图片是否互补衔接；检查正文中后段，不能只检查开头。来源和映射放制作备注，读者可见正文保留自然表达。文末互动及可选产品承接继续由各自模块负责。

写前执行 [策划前置与正文融入](../hook-generator/references/hook-library.md#策划前置与正文融入严格执行)。正文采用策划时已写出的具体钩子，对照主对标如何引出、展开和兑现；对标没有钩子时，在写前映射中安排本篇钩子的自然融入，保留原模块和逐句覆盖。不能先写自由稿再补钩子，不能只套抽象机制标签。

## 固定交付结构（严格执行）

正文交付结构为正文内容与适用的文末互动；产品承接仅在本篇product_mode=on时由product-amplify生成后整合。off时完整正文不要求出现产品，pending在策划审查时解决，不强加产品段。

body-writer不另写产品承接。启用后调用product-amplify取得实际文案及对应位置，合并检查语气、主题和前后逻辑；功能或承诺变化回用户复核。漫画故事中的产品方案在故事/分镜定稿前共同校准。评论钩子沿用原有适用规则，不能用产品句替代。

交付检查依据本篇启用状态：on核对承接实物与文案；off标不适用；已启用未完成不得标为整篇完成。

## 对标逐句模仿（严格执行）

执行 [正文逐句对标执行与验收](references/sentence-alignment.md)，在本篇制作备注维护实际源句到成稿的完整对照与整篇推进检查。下列原则以该记录落实；仅声明读过、参考过或列两处例子不能放行。平台writer须回读同版本记录再推进阶段。

每轮初写、局部改稿和全文重写，先执行 [每次写作与改稿重新对照原文](../writing-core/SKILL.md#每次写作与改稿重新对照原文)。用户提出修改意见后，必须重新完整读取正文主对标，再按本节校准语气、节奏和行文；不得用此前的分析或现有AI稿替代原文。本节的写前映射与写后并排复核同样适用于每一轮改稿。

完整单元按原文实际阅读任务和连续上下文划分：记录起止位置、读者问题、各句作用与前后关系。它可能是表前句加表格和贴士，也可能是场景到问题、解释到例子、条件到动作的一组连续段落；不固定句式或组成部分。单元是防漏的分组，不能替代组内逐句对应，也不能以“作用大致相同”合并掉具体句子。副标题、括注、提醒、例子、转场及结尾均归入原位；跨单元承接单独标明。写后同时核对组成是否齐全、每部分是否发挥原有作用，例如表后贴士若只复述表格，不算补充执行帮助。

**完整结构先验收，再核对句子。** 用户要求完整复刻时，按原文顺序保留章节、重复模块数量、各模块前后文字及其作用；不能自行重分组、跨表搬运句子后声称对应完成。每张表以“表前引导句／小标题中的具体重点 → 表头与逐行内容 → 表后贴士／承接句”为一个完整单元核对。原文有哪一部分就对应写出哪一部分；原文没有的部分不机械补齐。只有“周一”“孕早期”等分类名称不能替代原句中的重点、理由或收益。每张表分别验收，别处出现一条贴士不能抵消本表缺项。主题事实重新核验并原创表达，结构变更须有用户明确确认；未批准的分组适配保持未通过，不能靠审查表自行批准。

写前选定并完整读取正文主对标的连续原文及上下文。按原句拆解：语气与用词力度、句式和长短句节奏、信息先后、提问/接话/解释/例子/转场的作用、句与句及段与段的关系。逐句形成“原句及位置 → 写法与结构作用 → 本篇对应句及本篇事实依据”的映射，再落笔；不能只参考话题、字数、小标题或 Emoji。

**双向逐句覆盖是放行条件。** 先从原文建立按阅读顺序编号的句子清单，包含开场、转场、独立提示、表格每行、总结与结尾；网页导航、账号组件另行标识。每个源句记录具体位置、语气/句式/信息作用和本稿对应句；相邻句确需合并时列出全部源句编号与保留作用，不能静默跳过。个人身份、主题不适用或错误事实逐项记录具体适配及对应文本，不把整段笼统划为“原创承接”。然后反向逐句检查本稿的来源或明确新增理由。只检查已写出的句子、所有行填同一句“整体结构”、缺少源句覆盖，均不放行。正文数量与分组适配单列，不能把有映射写成原样复刻。引用原文使用必要短摘及位置链接，不在审查表大段复制原文。

写后将原文与本稿逐句并排核对：语气是否丢失、重点是否拖后、具体信息是否变虚、句间推进是否断裂、是否只剩通用套话。每句需有对应写法或明确的必要原创承接说明，不要求句数硬凑一致。借鉴语气和文本结构，用本篇事实与自己的表达写作，不做逐词同义替换，不照搬独特原句、经历或产品事实。产品承接另按 `../content-writer/references/stage-critique.md` 的独立写法对标执行；评论钩子按真实评论回答反推。

## 执行

图文正文在写前及交付前均执行 [正文与图片的互补](../writing-core/SKILL.md#正文与图片的互补) 的主题边界检查：先写清图片主题与正文补充点，再逐段核对直接关系。评论副问题、整餐示例或产品转场一旦变成另一条主线，即退回修改；不能以“避免重复图片”为偏题理由。汤谱正文展开整餐搭配，即使事实正确也不放行；必要搭配提醒按该规则放在产品承接前一句带过。

1. 公众号先完整读取正文主对标与已存分析，按章节任务、论据、例子、转场组织完整长文；正文不能缩成配图提点，图片未生成不构成缺项。以下图片前置及少量补充要求仅用于小红书图文：实际读取所选对标已存分析中的逐页任务、整组推进及正文如何补充图片的部分，引用原分析链接与章节，再通读本篇整组实际图片，写清正文需要提点、整合或补充的少量信息及其与图片的分工。按 `writing-core` 的正文与图片互补规则，保留有解释、整合、强调和阅读牵引作用的重合信息；长期已确认的有效表达和篇幅规则引用 `../content-writer/SKILL.md` 的正文相关章节，不丢失具体例子与理由。
2. 读取用户洞察与已选评论；凡描述用户处境、困扰、愿望或情绪，先按 `writing-core` 定位适用于本篇的用户洞察条目、证据及审核状态。单条评论或AI写回的待审核线索不能直接套成读者情况；没有有效依据时删去该假设及其推导建议，直接给有依据、可照做的主题信息。评论用于表达和互动参考，不为满足评论引用而硬塞困扰。
3. 按实际内容顺序逐模块写开头、信息模块和互动，启用的产品句由product-amplify提供；每完成一个立即执行 `writing-core` 的逐句四项 critique 和逐模块检查，通过后再继续。产品承接按篇启用，正文内部模块及自然段数随内容，不机械套固定句数。
4. 产品段沿用本篇已获批能力与说法；改变能力或承诺时回到用户复核。文末问题独立审来源、与主题关系、可回答性，避免为了评论编造困扰。
5. 完成后先按本篇product_mode检查实际交付和逐句对标、逐句 critique 的全文覆盖，再连读标题与正文（已有实际图片时一并核对；公众号成图后的合并验收在 WX7），检查承诺、重复、信息负担与自然衔接；执行 `../content-writer/references/stage-critique.md` 的适用检查及账号词库核查。用户批准的原句只在问题和受影响上下文范围修改。

写入当前平台独立飞书文档的 AI 初稿；critique 与来源放制作备注，不创建本地正文副本，不代填用户最终发布稿。小红书 Hashtag 交 `../hashtag-writer/SKILL.md`，固定10个；公众号不继承此数量。文末保留评论钩子，取消每篇固定求赞，不能将未出现点赞邀请判作漏项。
