# 内容采集助手

用于把用户提供的小红书笔记信息，或用户已在浏览器打开的笔记，整理到飞书知识库的 `02_内容素材`。这里的“文件夹/文件”是飞书知识库中的父文档和子文档，不创建本地替代文件。

## 读取与来源边界

1. 开始前读取 `00_个人背景/定位总览_v0.1.md`，但只用于了解项目范围；素材记录本身只保存用户提供或页面实际可读的信息。
2. 小红书页面优先使用用户打开的浏览器页面读取；不得用命令行抓取小红书页面替代浏览器。飞书知识库的查找、创建和编辑使用 `lark-wiki` / `lark-doc`。
3. 允许用户直接提供社媒助手导出的完整笔记信息。字段缺失写“未提供”或“未采集”，不推测、不分析、不改写用户提供的正文。
4. 判断笔记类型为“图文”“视频”或“长文”，以用户信息和页面实际内容为依据；无法确认时记录“未提供”，不要猜测。入库后按 A 类视频、B 类图文、C 类长文归入对应父文档，并按该类别连续编号。
5. 新入库的 B 类图文必须先查看当前笔记的主题、内容形式、图片组织方式和已有图片分析，再决定子分类。优先放入已有匹配的 B 类子分类；没有对应分类时，先说明依据并创建新的子分类父文档，再将素材放入其中。不能为了凑分类而强行归类。

## 参考用途

候选与入库检查报告增加“参考用途”：内容与视觉对标、需求线索、产品表达参考，可多选并说明具体可借鉴处。正式素材的点赞、时间、AI 适配与用户终审标准不变。

低赞的具体求助、功能演示或疑虑可以作为研究线索交接 topic-generator / product-amplify，附原帖、日期、原话和证据范围；不自动入库、不计入合格高互动对标。只看见产品展示时称“产品表达参考”，没有可核实的成交或使用数据不能称转化成功。用途记录放候选清单/检查报告，不插入原始笔记正文或破坏固定子文档模板。

## 候选筛选标准

这些标准在下载、建文档和编号前执行；不合格候选直接跳过，不能先入库再把它当作可用对标。

1. 点赞量 1000 是常规参考线，不是脱离发布时间和细分主题流量的绝对门槛。孕期便秘图文的常规参考线为 500 赞；其他主题默认仍为 1000 赞。低于对应参考线时必须同时展示准确发布时间和点赞量：若发布时间较近，可保留在候选清单中交给用户判断，不能自动淘汰，也不能自动入库；发布时间不近且明显低于对应参考线时排除。点赞量或发布时间不可见时标记为“数据待核查”，不能由 Agent 自动判定合格。用户已经逐条明确批准的候选视为通过终审，可进入后续查重和入库，但页面实际数据仍须如实采集。只使用采集当时页面可见数据，不推测历史峰值。
2. 对标必须适合后续用 AI 复刻其图片结构和视觉形式。优先选择信息图、插画排版、清单卡片、步骤图、食谱成品图，以及结构清楚、可由现有内容重新编排的图文模板。
3. 原则上排除以真人、手持商品、居家生活场景、店铺货架、品牌包装展示、强个人环境或纪实体验为主体的实拍笔记。这类图片依赖真实人物、商品和现场，AI 难以稳定复刻，不能仅因点赞高就入库。
4. 食物相关实拍可例外保留，包括菜品成品、食材、烹饪过程和摆盘步骤；前提是 AI 能稳定生成或复刻，且图片结构对后续食谱内容确有参考价值。仅手持饮料、补剂包装或商品陈列不属于该例外。
5. 混合图片组按核心模板判断：若封面和多数关键页依赖不可复刻实拍，则整条排除；若实拍仅用于展示食物成品或制作步骤，且主要排版结构可复刻，可以保留。
6. 通过门槛后再检查主题相关性、信息量与模板适配性。候选必须能为当前账号提供可借鉴的标题、正文、图片结构或内容组织；只有热度、但内容空泛或模板与可生产信息量明显不匹配的笔记不入库。
7. 预筛出的候选必须逐条在用户可见的浏览器标签页中打开，并向用户提供标题、链接、发布时间、点赞量、视觉形式、建议保留/排除及理由。到此暂停入库，只有用户明确指出哪些候选可以入库后，才能下载图片、创建编号或写入飞书；没有用户最终筛选结果时不得自行决定入库。
8. 每批用户筛选完成后，总结“被批准素材的共同特点”和“被拒绝素材的主要原因”，写入本次入库检查报告的筛选复盘部分。下次搜索前先读取最近的筛选复盘，用它优化搜索和预筛，但不得把一次样本的偶然特点自动升级为硬规则。
9. 采集反馈中记录搜索结果查看数、送审候选数、用户批准数，以及被跳过候选的主要原因（发布时间与点赞表现、实拍不可复刻、主题不匹配、信息量不匹配、重复）；不得省略“近半年发布＋最多点赞排序”的搜索筛选条件。

## 入库模板与层级

每条素材必须创建为“类别编号父节点＋固定子文档”的层级，不能把整条笔记正文直接平铺在类别目录下，也不能只创建一个混合文档。

- A 类视频：创建 `A类NN_标题_笔记ID` 父节点，下面固定创建 `笔记信息` 和 `视频解析`。
- B 类图文：创建 `B类NN_标题_笔记ID` 父节点，下面固定创建 `笔记信息` 和 `笔记图片`。B 类父节点必须继续挂在匹配的 B 类主题子分类下，例如“B类-孕期补剂安排”“B类-一日餐次搭配”“B类-营养目标型食谱”“B类-单品饮品食谱”；不能把饮品、补剂、餐次搭配和营养目标型食谱混放。
- C 类长文：创建 `C类NN_标题_笔记ID` 父节点，下面固定创建 `笔记信息` 和 `长文正文`。长文只有在正文体量和页面形式确实符合长文时才归入 C 类，不能把高信息量图文误判成长文。

编号在对应类别内连续递增；标题、类别、笔记 ID 和主题子分类必须与当前账号父节点下的既有命名保持一致。创建后要读取父节点，确认两个固定子文档存在且顺序正确。

## 入库流程

1. 先读取最近一次入库检查报告中的筛选复盘，再按“近半年发布＋最多点赞排序”查看搜索结果，并按“候选筛选标准”预筛。把候选逐条在用户可见浏览器中打开，展示日期、点赞量、视觉形式和建议理由，等待用户最终筛选；只有用户明确批准的候选才进入入库流程。随后定位 `02_内容素材` 父节点，读取其 A/B/C 分类及 B 类下的子分类父文档，按笔记 ID 和笔记链接查重；已存在时不重复创建，报告匹配到的文档。
2. 入库前先读取一个同类别的现有结构样例，确认父节点标题、子文档名称、顺序和内容分工；未完成样例核对前不得开始批量创建。
3. 按“类别父节点 → 固定子文档”创建结构；类别父节点命名为 `A类NN_标题_笔记ID`、`B类NN_标题_笔记ID` 或 `C类NN_标题_笔记ID`，不要用未带类别编号的标题作为素材父节点。标题中不适合文档名的字符只做必要替换，正文保留原始标题。
4. 将基础信息完整写入固定的 `笔记信息` 子文档。必须先打开同类别既有样例并复刻其结构；当前标准模板为：一级标题 `笔记信息`，其下使用一个无序列表，字段严格按以下顺序排列：`笔记ID`、`笔记链接`、`笔记类型`、`笔记标题`、`笔记正文`、`Hashtag`、`博主ID`、`博主昵称`、`点赞量`、`收藏量`、`评论量`、`分享量`、`发布时间`、`更新时间`、`图片数量`、`采集时间`、`笔记封面链接`、`笔记图片文档`；随后增加二级标题 `笔记图片链接`，按原始顺序列出全部图片链接。三类文本必须严格分离：标题只写页面标题；正文只写原作者正文，不重复标题、不包含 Hashtag；Hashtag 按页面原顺序单独记录，不并入正文。正文不得混入评论区、采集说明、图片分析或临时中间稿；缺失字段明确写“未采集”，已确认没有 Hashtag 时写“无”，不得擅自补写。子文档标题必须保持为 `笔记信息`，不要用笔记标题覆盖它。
5. 图文笔记的全部图片只写入该素材父节点下的 `笔记图片` 子文档。必须先打开同类别既有样例并复刻其结构；当前标准模板为：一级标题 `笔记图片`，紧接一个且仅一个三列表格，表头和列顺序严格为 `图片序号 | 单图分析 | 图片`；每张原图占一行，第一列写 `第N张图片`，第二列写基于该张实际可见内容的具体分析，第三列嵌入下载后的实际图片块。图片必须从原始页面下载并嵌入飞书文档，不能只记录远程 URL、资源 ID、图片小标题或“以原图为准”。按原始顺序处理全部图片；图片中的可读文字与画面内容写入图片块的 alt/说明，不能另造一套与既有模板不一致的“图片正文”列。入库时必须完成每张图片的单图分析，不能把“未分析”作为正常完成状态。子文档标题必须保持为 `笔记图片`，不要被笔记标题覆盖。
6. 单图分析应基于实际可见内容，至少记录：该图承担的内容任务、主要信息层级、文字与内容的组织方式，以及可直接观察到的版式/表达特点。不得把不可见内容、效果或用户反馈写成事实；无法读取的图片只记录具体路径和“无法读取”，不推测。
7. 在三列表格之后直接增加二级标题 `整组图片分析`，分析整组图片的内容顺序、每张图之间的分工与衔接、整体信息组织方式、信息量与所用模板是否匹配，以及首图与后续图片的关系。不得在表格前后额外创建“图片与单图分析”“图片素材与分析”等非模板章节。整组分析必须以实际图片内容和序号为依据，不用“整体清晰”“很有吸引力”等空泛结论代替。
8. 视频笔记：在同一个父节点下写入固定的 `视频解析` 子文档，至少包含标题和“原视频链接”字段；原视频链接必须是小红书笔记链接，不要写下载后的 mp4 链接。逐字稿由用户后续手动补充时，保留其原文，不擅自转写或分析。
9. 长文笔记：在同一个父节点下写入固定的 `长文正文` 子文档；保留页面实际可读的长文正文，不把图文图片文字冒充长文正文。
10. 笔记正文为空时如实记录“未提供/未采集”；不要把图片文字冒充笔记正文，也不要因有图片就替正文补写。

## 入库检查

这是每次采集入库的固定收尾步骤，不需要用户另行提醒。所有本次素材写入完成后，必须读取并更新 `02_内容素材/_入库检查报告.md`。检查时排除 `搜索关键词.md`、`_入库检查报告.md` 和其他以 `_` 开头的辅助文档；只有同时具备标题、来源链接和可读正文的条目才算有效内容。检查嵌入图片是否存在且可读取，并分别记录缺失或无法读取的具体路径。报告中的有效内容总数、入库路径、重复项、缺失字段、图片资源问题和“是否达到目标”必须与本次实际检查结果一致，不能保留过期结论。

## 写入与反馈

- 只修改 `02_内容素材`及本次明确要求的入库检查报告，不改动其他知识库分区。
- 写入后重新读取目标文档，核对标题、笔记 ID、来源链接、正文、类型和图片/视频链接未丢失。
- 写入后必须重新读取素材父节点，确认父节点下存在且仅存在本类别规定的固定子文档：A 类为“笔记信息＋视频解析”，B 类为“笔记信息＋笔记图片”，C 类为“笔记信息＋长文正文”；子文档缺失、名称错误、顺序错误或把内容写回父节点时，不能视为入库完成。
- 对 B 类逐条复核：`笔记信息` 含上述 18 个固定字段且顺序一致，标题、正文和 Hashtag 分开，正文不重复标题且未混入评论；`笔记图片` 只有标准三列表格和其后的“整组图片分析”，表头严格为“图片序号｜单图分析｜图片”，数据行与实际嵌入图片块数量都等于原图数量；两个子文档标题仍分别是“笔记信息”和“笔记图片”。如果写入内容后飞书自动改变了子文档标题，必须立即改回固定名称。
- 所有本次素材写入并复核后，必须更新 `02_内容素材/_入库检查报告.md`；未更新报告不得宣布本次入库完成。
- 入库检查报告必须记录本次筛选条件、每条用户批准素材的发布时间与点赞量、图片组 AI 复刻适配性，以及用户最终筛选结果。低于对应主题参考线但因发布时间较近或用户终审通过而入库的素材要单独注明，不能写成“全部点赞量均达到门槛”。
- 新入库图文完成后，核对素材所在的 B 类子分类与当前笔记主题和内容形式相符；若新建了分类，记录新分类名称及创建依据。
- B 类图文写入后，逐项核对图片表格是否覆盖全部图片、顺序是否正确、每张图片是否都有具体“单图分析”，图片 alt/说明是否反映可见文字和画面，并核对文档中是否存在“整组图片分析”；禁止保留“以原图为准”“记录其版式供后续匹配”“第N张承担具体信息展开”等占位式描述。后续补充分析时只补充分析字段，不改写原始图片内容。
- 完成后报告：搜索筛选条件、查看候选数、通过数、各类跳过原因、文档位置、是否重复、图文/视频类型、图片计划数量、成功/失败数量、正文是否为空；若更新了入库检查报告，再报告当前有效内容数量。
- 不把内容分析、规律提取、选题或创作混入采集流程；这些任务使用对应的其他 Skill。
