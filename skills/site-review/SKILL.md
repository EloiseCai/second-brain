# Site Review

## 触发边界

当用户明确要求“复盘”一个已经上线的网站时使用本 skill。一次请求对应一次新的复盘文档；不要因为网站已上线、已有历史复盘或日期变化而自行触发，也不要创建定时任务。

如果用户没有提供网站 URL 或可识别的网站名称，先询问要复盘哪个网站。若用户没有提供统计数据，不要猜测或编造数据；先创建表格，并将相应记录单元格留空或标为“待补充”。

## 固定归档位置

每次复盘都在以下 Wiki 节点下创建新的子文档：

`https://my.feishu.cn/wiki/VUU7wsGhWiLcVskrgKzciIiznYc`

优先以用户身份操作。先使用 `lark-wiki` 解析父节点并创建新的子节点，再使用 `lark-doc` 写入文档正文。执行文档创建与正文写入前，读取对应技能中当前场景所需的创建工作流参考；不要把 Wiki URL 直接当作文档标题或 space ID。

建议标题格式：`网站复盘｜<网站名>｜<YYYY-MM-DD>`。如果同一天已经有同名复盘，在标题末尾追加时间或序号，确保每次请求都得到一个新文档，不覆盖历史文档。

## 文档内容

新文档至少包含：

1. 标题或开头说明：网站名称、网站 URL、复盘日期、统计时间段（未知时标为“待补充”）。
2. 一个两列表格。左列为指标，右列为“记录”。表格字段按以下顺序创建：

| 指标 | 记录 |
|---|---|
| 统计时间段 | |
| 总展示量 | |
| 总点击量 | |
| 平均排名 | |
| 前 5 个搜索词 | 1.  2.  3.  4.  5. |
| 出现了哪些你没做页面的词 | |
| 哪些页面没被收录 | |
| 下一步补哪 2–3 个页面 | 1.  2.  3. |

表格应尽量复现参考图片的语义和布局：左侧是字段名，右侧是记录；“前 5 个搜索词”和“下一步补哪 2–3 个页面”保留编号填写位。可以改善可读性，但不要删减这些字段或改成每日流水表。

3. 如用户同时提供了具体数据，将数据填入对应记录单元格；无法确定归属的数据放在表格下方的“待确认”说明中，不要自行推断。
4. 如用户要求进一步分析，再在表格下补充简短的观察和行动项；默认只初始化复盘文档与表格，不擅自扩展为完整 SEO 报告。

## 完成检查

完成后确认：

- 返回新建文档的标题和可访问链接；
- 文档确实位于指定父 Wiki 节点下；
- 表格包含全部 8 个字段，顺序正确，指标缺失处没有伪造数值；
- 本次操作没有修改或覆盖既有复盘文档。

若创建子节点成功但正文写入失败，保留该新文档并说明失败阶段；不要为了重试而重复创建多个子文档。优先在同一文档上继续完成正文写入。
