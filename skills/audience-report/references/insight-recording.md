# 长尾词与自然语言洞察（2026-10-09确认）

## 搜索栏下拉词 → 逐词查量 → 统一词库

每轮主动研究先读旧词库，按本轮主题选择已有父词和新增种子。小红书实际输入关键词，完整记录当次可见下拉词原文、父词、出现位置、页面或截图和采集日期。可用新下拉词继续拓展；模型扩词另标检索假设，不能混成平台返回。去重后逐个查询新增下拉词的可用流量数据，旧词需要刷新时更新原行，不重复建库。没有新增可用词如实交付，不凑数量。

实际下拉词即使是完整问句也保留原貌，可标为问句型长尾词；自然埋词适配另判，不能为了短词规范丢弃平台原始表达。搜索下拉词与结果页相关搜索分别注明来源位置。

记录指标原名、原值、单位、统计窗口、数据平台、取数日期及来源。搜索量、搜索指数、话题浏览量、笔记浏览量不能互称或混排。查不到用未收录/未披露/无权限/未查询等实际状态，不填零。统一关键词表按同平台同指标同窗口分组排序；保留旧数值对应日期，不把历史快照当本轮数据。词库只维护一份，记录父词与关联问题ID。这一步属于 audience-report，不受热点雷达关闭影响。

## 六维记录

字段定义、具体任务的自然语言标准、推理归属及逐行critique统一执行 [六维分析与生成标准](../../research-core/references/six-dimensions.md)，不另维护定义。核心痛点承载由处境推导的关切、顾虑与期待；当下情绪仅记录感受词。原话与推理分开，下游引用仍保留证据性质。

## 实际困惑的呈现

实际困惑使用逐条自然语言卡片，不使用大表格。关键词数据和六维概览仍可用表格。每条以稳定问题ID、具体问题为标题，先放可追溯的用户原话，再用连贯文字说明场景与障碍、当下情绪及在意的事情、真正希望得到的帮助。减少“需求缺口、任务转化”式术语，不机械堆字段或重复原话。

来源段必须有原文短摘录、作者/评论身份（可见时）、原文链接或明确文档定位；不能只给来源编号或分析摘要。作者自述、评论、创作者设问分别标明。没有用户原话时保留现有内容来源并写清是内容推断/搜索线索，不将归纳句加引号冒充原话。来源补齐前不称已完成原话核验。

取消“人工审核/用户审核”栏、未看/未审核等占位及强制审核队列。已有具体用户纠正、退回理由和使用范围保留为有效内容约束；用户删除的条目不得在后续调研中无依据恢复。来源性质和证据状态继续保留，AI仍必须执行 critique。

## 逐条 critique

核对原话是否原样、出处可定位；分析是否回应同一场景；情绪推理是否写出依据且未夸大；六维是否逐项考虑；是否用自然语言讲清用户在想什么、卡在哪里；搜索指标是否同口径；是否清除人工审核占位且保留有效纠正。失败项修正后回读，记录实际完成范围。
