# 用户洞察统一写入关口（2026-10-10确认）

## 唯一入口与最新规则

所有《用户洞察》写入（新增、补证、纠正、合并、六维、关键词及表现回填）统一调用 audience-report。pattern-extractor、topic-generator、writer、review、其他模块和用户反馈均适用，包括独立调用、批量任务与断点续做。它们负责收集原文和提出分析，不能用自己的格式或旧摘要直接更新洞察文档。

每次准备写入时，实际重新读取项目当前 audience-report/SKILL.md、insight-recording.md、research-core/references/six-dimensions.md 及当前主题包绑定的位置；校验本机运行副本与项目版本一致，不一致先按 skills/README.md 同步。读取当前文档全文和本次原始证据，不能依赖会话记忆中的字段定义。方法只引用唯一规则，不在各模块复制六维模板。素材分析仍由pattern-extractor负责；《用户洞察》的字段、自然语言、推理归属、去重及验收以audience-report及其当前引用为准。

## 触发与时点

模块完成研究、准备向下游交接之前，必须检查是否有洞察增量：新原话、场景、痛点、反例、来源、已查询关键词指标、用户纠正或真实表现数据都算增量。

- 有增量：当场执行 audience-report 的增量回写模式；critique、写入并回读成功后，才能完成模块交接。独立模块同样在最终交付前执行，不等待用户再次安排。
- 无增量：在当前任务的交接记录写“无新增”及已核对的洞察位置，直接继续；不向洞察文档追加无新增日志。
- 写入失败或回读不符：保留材料与失败原因，状态写“待回写”，先修复再恢复交接；不能当无新增跳过，不能报告模块已完成。

增量回写仅整合已取得材料，不重新启动五路调研、热点扫描或全库重分析。已有来源重复出现时补充有实质差异的内容；同一来源同一原话同一版本无新信息时不重复写。纯写法规律和生成的文案不作为新用户证据。

## 输入与执行

上游交付：账号及目标文档、当前模块/任务、来源URL或文件定位、必要原话与上下文、来源类型、日期及指标口径（如有）、已有问题ID与用户纠正、建议增量。分析与原话分开；缺字段只补本次所需证据，不捏造内容。

按顺序执行：读取最新规则与全文 → 核对原文 → 比对已有问题和来源 → 按最新六维与自然语言标准整理 → 逐条critique并修正 → 对应章节原位写入 → 回读对照 → 返回问题ID与链接。

检查任务是否说清想完成什么、场景是否具体、身份是否为人群称谓、阶段是否为当前状态、推理关切是否归核心痛点、情绪是否只写感受、障碍是否解释原因。问题卡保留原话与自然语言，取消人工审核占位；来源、有效用户纠正、关键词指标及其他章节保持完整。指标回填不强造新的六维或问题。

## 交接与恢复

在上游现有任务记录中保存：实际读取的规则路径与时间、insight_writeback=written_and_verified/no_change/pending、问题ID、目标链接/锚点、写入后修订号或更新时间、critique与回读结果、失败原因（如有）。这些是制作记录，不放进读者正文，不另建并行用户洞察库。

只有 written_and_verified 或经实际比对的 no_change 才放行。恢复 pending 时先回读目标，判断上次是否已写成功，避免因工具响应中断重复新增。上游接收返回的ID与位置后继续，不回到完整研究入口；既有用户选题、文案及产品审批点不被此内部写入动作替代。
