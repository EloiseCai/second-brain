# 六维组合、人群问题库与验证 SOP

2026-09-25按用户补充修正：六维既是发现问题的生成工具，也是调研后的归纳结构。允许先推演问题，再找证据；禁止的是把推演当真实用户事实。本文是本账号的试行执行机制，批次数量用于控制工作量，不是统计证明。

## 1. 先列六个维度的选项池

读取固定飞书《用户洞察》全文，复用其中维度选项、问题ID、用户审核和测试记录。每维独立列举，合并近义项；每项记录维度ID、名称、定义、来源或“AI探索种子”、适用条件、最近更新。不要每轮清空重建。

| 维度 | 列举方向（探索示例，未验证） |
| --- | --- |
| 生活场景 S | 通勤前、工作午休、外出点餐、采购、准备产检、家庭讨论、临睡前、待产准备 |
| 人群身份 I | 首次怀孕、已有孩子、上班、轮班、独自安排生活、家人负责餐食；这些可重叠，不能推断收入或性格 |
| 孕周阶段 G | 孕早期、孕中期、孕晚期、明确的孕周；不得把不同阶段同时赋给一个场景 |
| 核心痛点 P | 不会选、不知道怎么安排、信息矛盾、不会执行、替代方案不合适；此处是问题类型，不是具体问题结论 |
| 情绪 E | 担忧、纠结、疲惫、委屈、厌烦、期待、好奇；组合时是情绪假设，调研后另记原话及未知项 |
| 行动障碍 B | 时间短、条件不足、信息散、成本高、缺少支持、步骤复杂；标明是否有直接证据 |

扩库时执行 [增量扩库与关键词量化](incremental-research.md)。上表仅是一级分类，不是足够具体的选项库。初次全人群建设以40—60个任务场景、20—30个具体卡点为探索规模；身份、情绪、障碍各扩到12—20个有实质区别的条件，阶段保留真实分期及证据明确的孕周，不为凑数拆阶段。数量是覆盖目标，不是用户需求事实。

六维可以各自生成，但不要穷举全部笛卡尔积。核心痛点与障碍有重叠时合并解释，不靠换词制造新问题；情绪不强制都是焦虑。

## 2. 有目的地组合，形成具体问题假设

先选一个场景和身份，再选择兼容的阶段，追问此时要完成什么任务。用痛点、障碍和情绪池检查可能卡住的地方，补齐六维；无法合理组合的项剔除并记录原因，缺少信息允许留空。也可以从已见搜索词或真实问题反向补齐六维。

问题句式：**谁，在什么时刻，想完成什么具体任务，因为何种限制而卡在什么选择，希望得到什么结果。** 情绪另列“当下感受及触发原因 / 希望获得的感受”，避免把安心等目标感受当成当前情绪。

示例仅为AI假设：上班的孕早期妈妈，在出门前准备早餐，只有十分钟且不想开火，希望吃完能出门，却不知道如何快速选一份能接受的早餐；可能着急或担心，情绪仍待核实。由此生成检索问句，再查实际下拉词、笔记与评论。不可写成已经采访过这个人。

初次全人群探索先形成40—60个有实质区别的组合假设，按覆盖缺口筛出10—15个优先补证问题；最终选题交付量与问题库规模分开。后续每轮先读全库与生成记录，尝试补充15—25个未覆盖组合，语义去重后只入真正新增项；重复项原位补证，不重发旧清单。范围小、差异不足时少出并说明，不凑数。各批未深查项保留生成假设及补采状态；不能把广泛生成称为已完成调研。

## 3. 组合与搜索双向补证

执行 research-workflow.md 的五路调研：实际搜索词/下拉词、可访问的数据平台、热门笔记与近期求助、评论与真实反馈、同类孕妈 App／小程序及公开评价。搜索与产品观察既验证组合，也独立发现组合池遗漏的问题，补回维度选项。搜索无结果只记本次未找到，不判定不存在。

每个入选问题先拆成“人群/阶段词＋任务词＋场景或限制词”，用实际出现的短关键词及近义词检索，再到帖子与评论核对完整问句、现有办法、不适用或已解决的反例。完整问句归问题卡，不为了取指数把它当关键词。记录真实查询、日期、窗口和渠道缺口；不把所有来源强行塞进每张卡，但每轮必须核查五路渠道。第二轮单题完整阅读至少3篇独立相关笔记，沿用topic-generator既有标准。不要为凑样本挑选一致意见。

## 4. 定义并入库一个问题

固定ID使用PB-P001起递增，先查已有ID避免冲突；AR编号继续作证据编号，不重排旧素材。去重键为“任务 + 触发场景 + 实质障碍”。身份或孕周确实改变解决办法才拆子问题；只换情绪、标题、菜名通常保留同一问题ID。

每张问题卡必须有：问题ID与一句话问号、六维组合ID、原话与来源、AI解释、现有办法与失败点、情绪原话/推断、支持与相反证据、下一步补查、问题状态、用户审核。只有泛泛的“需要健康/营养/省心”时退回具体化。

问题状态分开记录：

- **生成假设**：来自六维组合，尚无直接表达。
- **已有直接表达**：至少一条可追溯求助、实际输入、访谈或明确提供的本人困惑，能定位具体任务；仅证明有人问过。
- **交叉支持**：不同独立来源支持同一具体问题，写明来源数与差异，不推断普遍性。
- **待修正 / 暂缓 / 合并**：保留原问题、理由、日期和归并ID，不删除反证。

另设“用户审核：未看 / 符合生活经验 / 需改写 / 暂不认可 + 原话、日期、适用条件”。用户审核是产品判断；本人真实经历另作来源。不把用户认可或多篇流量自动改写为普遍需求。

### 4.1 来源到问题卡的逐条验收（严格执行）

提取定义引用 [pattern-extractor 核心需求提取](../../pattern-extractor/references/benchmark-analysis.md#核心需求提取严格执行)，角度保留引用 [writing-core](../../writing-core/references/angle-fidelity.md)，此处仅维护入库与整合验收。

1. **原文对应**：读取来源全文及相关图片分析／视频逐字稿，逐条对应“必要短摘录 → 具体处境与对象 → 忠实问号 → 问题ID”。原文中的时间、食物、口味、动作和选择保留下来；摘要与原文冲突时按原文修正。原文缺失就记录缺口，不能借已有摘要补齐。
2. **证据性质**：具体作者经历与真实评论可以支持相应处境；面向读者的问句、广告对话、方法清单属于内容角度。自称过来人不自动使后续所有问句成为亲身经历。作者自述可直接提供需求证据，营养效果是否成立另由原素材核验。来源性质按各个子问题分别标注，不给整篇只贴一个笼统标签。
3. **同卡不丢角度**：只有任务相同才归同卡；同一卡内仍分别保留来源支持的子问题。半夜饿醒、起床即饿、上班可携带加餐和一日六餐分开记录；喝腻牛奶、白水没味和补钙替换分开记录。发给 topic-generator 的是具体子问题及来源，不能只给“加餐安排”“饮品多样化”等上层名称。
4. **逐字段验六维**：人群、孕周、时点、障碍和情绪各自回到同一来源；未知写未说明。一般做饭者不自动变成孕妇；某一作者的孕周或情绪不能扩给同组其他素材。综合表只保留共同任务，差异写清来源，不能拼成一个不存在的人。
5. **合理合并**：补剂同日时间安排、补剂依据冲突、补剂选购与吞咽口感是不同任务；备物选择与记录胎动也是不同任务。新来源不适配已有ID时另建问题，保留旧ID及用户退回决定。搜索量和对标互动不升级为用户主动需求或需求频率；同一评论多处引用只算一条证据。
6. **方案与需求分开**：收藏多仍不会选、家中库存、购物清单、连续记录、自动计算等条件要各有来源。产品方提出的能力或闭环明确记为产品要求／方案假设，不改写成受众原话。具体功能有无及拟用表述由用户复核，不默认已有或没有专用方案。
7. **联动修正**：逐条更新来源记录、六维汇总、问题卡、关键词关联、方案状态、优先级及原素材回链；不让上方写“无直接表达”而下方已有自述。保留关键词原值和排序、真实原话、用户审核、发布表现与有效知识核验。将误挂来源从错误ID迁到正确ID，不靠重复挂多个宽泛ID掩盖不匹配。
8. **回读放行**：核对来源清单覆盖数和唯一AR编号、每条问号与原文是否一致、问题与素材是否双向匹配、关联ID存在、假设状态与用户审核是否保留。逐条寻找无依据的前提词、被抽掉的具体场景和产品倒推。发现一项不符就原位修复并重查；输出已实际修正的范围与仍不可读的来源，不宣称超出检查范围的完成。

## 5. 对同一个问题比较解决方案

每个优先问题至少比较现有替代办法与一个可交付方案；有实质不同的路径再增加，不硬凑三款功能。用PB-Pxxx-S01等ID关联问题，方案改版保留版本。

方案卡记录：帮她完成哪个动作、所需输入、执行步骤、具体输出、怎样绕过已知障碍、成本/信任门槛、内容可先交付什么、产品额外提供什么、已上线/待核实/未开发、事实依据、成功行为和失败信号。信息分散可能需要整理；时间不足可能需要缩步骤；缺少家庭配合可能需要沟通工具，不默认所有问题都交给食谱生成器。

选择顺序：能否直接回答问题 → 是否降低最主要障碍 → 承诺是否可兑现 → 能否低成本验证 → 产品适配与开发成本。优先级必须附证据和理由，不伪造需求分数。方案尚未开发也可用真实方法、清单或明确未上线概念研究兴趣，不能宣传成可用功能。

## 6. 一篇笔记对应一个主要待验证判断

角度使用PB-Pxxx-A01等稳定ID，记录切入矛盾、内容承诺和读后行动；只换标题或封面沿用角度ID，方案实质改版分开统计。topic-generator为每篇交接“问题ID + 角度ID + 方案ID/版本 + angle + 封面机制/版本 + 主要假设 + 指标/窗口 + 比较对象 + 保持条件”。content-writer延续关联。首轮可探索问题与方案的整体吸引力，不能假称已拆出原因。

后续比较按需要选择：同一问题和方案换表达，检查封面/标题；同一问题尽量保持表达换方案，检查方案吸引力；同一方案应用到不同处境，检查问题边界。非随机发布称顺序探索，记录发布时间、来源、人群、投放等差异。多因素同时变动时，只报告组合结果。

## 7. 仅回填组合表现统计

用户洞察负责汇总同一“问题ID＋角度ID＋方案ID/版本”下的多篇笔记数据。单篇指标含义、原因诊断、优化动作由review保存在单篇复盘，不在本库重复维护四类支持/削弱判断。

汇总表：组合ID｜问题/角度/方案简述｜窗口与投放口径｜发布篇数/有数据篇数｜观看合计及单篇中位数｜单篇CTR中位数｜CTR≥18%的篇数/有CTR篇数｜收藏合计｜笔记与复盘链接。按需增加可核实的涨粉或产品转化，不用同期产品新增代替单篇归因。缺数写未提供，不填0。

明细唯一键：账号＋平台＋笔记ID＋统计窗口；每个窗口取当前有效快照，更新原行，不能将同一篇多次累计快照相加。每篇一个主要组合；附带问题可做标签，不能重复计入。未确认历史关联标未关联，不凭标题强行分组。

第1天、第2天、7天、30天、最终累计分组；沿review的实际时间窗规则。平台、自然/付费流量可区分时分开，未知注明；最终累计注明各篇年龄，不能当同窗口排名。每项展示有效样本数，观看合计不代表去重人数。CTR使用平台原值；只有同口径真实点击数与曝光数齐全时才另算合并CTR，不能拿观看量代替点击数。

18%是用户确认的官方CTR中位数及目标。看“多篇都好”时同时展示CTR达标篇数，以及观看高于同账号同形式同窗口基线中位数的篇数/有效篇数；基线保存样本列表、数量与计算日期。没有基线就暂缺；不临时挑最有利指标给组合打分。此处只展示本账号样本表现，单篇结果不升级为稳定方向，高观看不自动证明产品转化。

## 8. 飞书唯一问题库与交接职责

所有账号内人群研究（audience-report、topic-generator、writer补查、review反馈、用户人工审核）统一归纳到主Skill指定的《用户洞察》。证据原文可以仍在素材/选题/复盘文档，问题、角度、方案和组合表现必须在此有索引与来源链接，不另建并行人群库。

固定结构为：使用说明 → 唯一关键词搜索表 → 六维选项池、具体任务场景与组合示例 → 问题索引与待审核项 → 具体问题卡/现有角度库 → 方案与桥梁 → 组合表现统计 → 证据与范围。六维必须留在人群洞察文档中，并写明组合怎样生成问题假设、情绪怎样用用户原话核对。读取当前全文后将新增内容插入对应区域；保留现有有效内容、来源、用户批注，按问题ID原位更新。关键词表新词按原始指数插入正确排序位置，不在末尾追加。

audience-report是问题库写入责任方。其他Skill取得新证据时生成并交接“问题/角度/方案ID、来源、原始指标与窗口、证据增量、用户意见”，由audience-report执行整合及回读；当前已授权范围内可以连续执行，不要求用户重复授权。无法写回时明确标“待回写”，不能报告已闭环。review自身仍不修改App漏斗列。

每次研究结束交付四件事：本轮新增/补强/合并的问题及方案；待用户审核的简短问题清单；尚未覆盖的组合和渠道；下一批内容拟验证的判断。只建议审核重点，不自动创建提醒或私信访谈。连续多轮主要是旧问题新证据时，转向解决方案和表达测试，出现新阶段、新处境或反例时再扩展问题库，不为数量不断造新问题。
