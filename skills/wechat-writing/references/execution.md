# 公众号执行与续做协议

唯一入口为 writing-router，阶段顺序以本包 SKILL.md 的 WX1—WX8 为准。沿用 writing-router/references/handoff.md 的账号配置与任务字段，不复制另一套账号知识。公众号稿单独建飞书文档。

## 每次恢复

通读当前稿和制作备注，核对平台、阶段、实际成品、已批准文字/方案及下一动作。旧记录缺字段时从当前稿与用户批准补齐；无法确认的批准不猜测。用户说“继续”只推进下一未完成子步骤。局部修改只回到受影响模块，保留其他批准。

| 阶段 | 放行依据 | 下一步 |
| --- | --- | --- |
| WX1 | 平台、账号、独立稿和选题来源明确；指定题只免第一轮 | WX2 |
| WX2 | 公众号主对标原文、逐模块拆解、逐句核对及事实证据已读；原有调研确认节点完成 | WX3 |
| WX3 | 正文 Brief、完整模块与源句对应、关键词和产品拟用说法清楚 | WX4 |
| WX4 | 标题和完整正文逐句 critique 通过并按既有节点送审；表前引导、表内信息、表后提示、转场均有对应 | WX5 |
| WX5 | 按正文位置规划两套独立对标方案；每图作用、文字容量、横向画幅明确 | WX6 文案审查 |
| WX6 | 完整图片文案获批→生成封面候选→用户选择→生成所选配图→实际图片验收；逐个记录，不合并成笼统“图片完成” | WX7 |
| WX7 | 标题、正文、图片在独立飞书稿完整交付，second-brain 文件与图序一致；复核主题、事实、风格、间距、文字和图文关系 | 制作收尾，或明确授权的发布准备 |
| WX8 | 有发布授权及真实发布记录才登记发布；有数据后复盘 | review |

图片批准不代替正文批准。产品说法变更引用主题资料并请用户核定。正文逐句对应执行 body-writer，完整单元执行 pattern-extractor；不遗漏表格前后的说明。

## 飞书状态块

记录：任务 ID／公众号长文／规则包版本／当前阶段与子步骤／主对标及分析链接／正文版本与审查状态／图片方案选择与文字批准范围／实际图清单与归档目录／待处理项／下一动作。

将“内容制作交付”“公众号编辑器排版与移动端预览”“实际发布”分别记录。用户要求收尾时可结束制作；未做发布端验证或发布，明确保留其未执行状态，不为完成流程自动发布。不要将具体某篇的实时进度写进通用 Skill。
