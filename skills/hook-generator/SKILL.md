# 钩子生成器

读取内容包统一Creative Brief、当前类型/平台策划、真实洞察与具体对标，组合 writing-core、平台和主题规则。执行 [钩子原话与规律库](references/hook-library.md)：从主题包的 hook_library 读取实际原话和规律，不能只读抽象分类。开头只是钩子的一个落点；标题、封面、信息包装、展示方式和利益点同样可以构成钩子。既有标题、开头规律原位保留并引用。

围绕前3秒注意力这个设计目标，规划读者最先看到什么、具体场景为何相关、哪个问题/信息差/画面让人停下、继续看的预期，以及后文如何兑现。3秒是创作检查视角，不冒充实际留存测试或保证。

记录标题、封面首屏、正文开头、漫画首格或视频开场分别承担的钩子作用，按本轮实际载体选用。由 title-writer 等在正式写作阶段落实成品；不在这里重复生成整套标题或文案。

交接必须保留“钩子ID及原位链接、完整参考原句、关键钩子词、吸引机制、本篇采用表达、使用位置、内容如何兑现”。由 title-writer、image-copy-writer、body-writer 等实际读取后落实，不能只交“好奇型”“省事型”等标签。适用的短表达可以直接保留，不为求不同而削弱力度；数量、身份、来源和效果随本篇真实材料核对。

## 深度分析与执行顺序（严格执行）

先执行引用协议的整篇阅读关口。标题、完整正文和整组图片共同构成分析单位；正文及图片中的独立吸引点与相互关系均须提取。只读标题的记录属于片段线索，不能作为整篇钩子方案已完成的依据。

钩子是内容让特定用户迅速觉得值得继续看的吸引机制。先解释读者已有的关切或认知、看到的具体信息、产生的期待和愿意继续看的理由，再分析词句、画面、观点与信息推进怎样共同完成这个作用。常用类别仅作检索标签，不能以“权威＋好奇”等标签代替解释。

按引用协议顺序执行：读取实际原话及上下文 → 分析读者语境与具体期待 → 找出组合表达及画面的作用 → 用删除/替换比较检查关键吸引力 → 根据本篇材料选择并安排落点 → 标出首次收获、后续阅读理由与兑现位置 → critique、修改复查、写入回读。已读原文的实际兑现与本篇计划兑现分开；缺原文时保留缺口，不补造已观察到的画面或结果。

正式交接以引用协议的完整字段为准，除原句外保留读者语境、期待、关键作用、画面配合、实际采用表达与分段兑现映射。标题/封面、开头和后续阅读分别安排作用；不同位置可以共同加强同一期待，不强制重复原句或每页制造悬念。成品方案、便利、情感认同和观点发现均可提供阅读理由，不强制所有钩子都具备悬念或机构来源。

critique逐项执行引用协议的检查表，写具体问题、改动和复查结果；只写“通过”不算检查。写入内容包本分支钩子章节，回读后交 story-builder / 平台writer。场景或内容承诺变化时回到本模块校准，候选数量、评分和实测效果门槛仍待细调。

通用方法在本Skill及引用文件维护；真实钩子、场景与案例分析保存在主题包绑定的飞书/已选后端文档中。
