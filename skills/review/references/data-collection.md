# 发布数据采集与快照

用户已授权自动采集本人账号时执行；单纯更新 Skill 不会创建调度任务。本参考维护采集方法，不保存密码、Cookie、访问令牌或未验证的接口。

## 先验证通道

1. 优先使用已连接且确实支持本人笔记分析指标的官方接口；核对授权账号和返回字段。没有已验证接口时，使用可用浏览器工具读取本人已登录的创作者后台。每次按工具当前文档操作，不固定猜测网址路径、按钮或选择器。
2. 确认后台账号与飞书 account_root 的对应关系，用笔记 ID/链接核对笔记，标题只作辅助。新帖只在身份和笔记对应关系确定后加入采集范围；匹配不清时留下待核记录。
3. 先完成一篇只读试采：进入实际数据详情、读取可见指标、记录统计范围与刷新时间；有导出功能时下载原始报表，保存证据并回读数值。接口可用、页面可读、定时可运行分别记状态。
4. 后台未登录时交给用户扫码，不索取凭据、不绕过验证码；后台不可读时，公开笔记只能补公开互动数据，不补造后台曝光、CTR、时长或搜索来源。
5. 通道未通过试采，不创建反复失败的活动调度，不宣称自动采集已开启。可以先完成采集计划和规则，并明确阻塞点。用户方便时导出的报表仍可自动整理，无须卡点。

## 采集计划

- 发布登记保存账号、笔记 ID、原始链接、发布时间与时区、时间来源/精度、最终稿/首图版本、对应飞书复盘文档。
- 目标观察时点为发布后 24 小时、48 小时、7 天、30 天；7/30 天为当前试行长期观察参数，可按实际反馈调整。目标时点独立于实际采集成功时间。
- 已授权且试采成功后，先检查现有自动化，复用同账号任务避免重复。Codex 中使用 automation_update 的当前能力创建本任务 heartbeat。默认每天在用户常用复盘时间固定运行一次，只采集已到期且未完成的目标，避免高频轮询和重复遍历全部历史笔记；只有用户明确要求严格贴近 24/48 小时窗口，才根据发布时间安排临近目标点的一次性或低频检查。运行频率与固定时间以用户要求为准。
- 保存实际任务 ID、计划、目标账号、读取范围、写入位置、最近成功时间与失败原因；工具明确返回启用成功后才报告“已开启”。安装 Skill、写了计划或一次手工成功不能替代这一步。
- 本地任务依赖运行设备、可用浏览器和有效登录；按调度器实际能力说明休眠/离线限制，不保证无人值守或准点。逾期恢复时一次采当前快照，给错过的目标标记缺失，不用同一晚到快照假装填齐多个时点。
- 没有到期项、数据未变化或仅常规成功时保持安静；需要重新登录、持续采集失败或出现可行动的变化时才通知。相同阻塞不每小时重复提醒。到 30 天后该笔记结束本轮采集，明确续监时再延长。

## 快照字段与存储

每份快照记录：账号根节点、平台账号、笔记 ID、目标时点、实际采集时间、平台统计起止/更新时间、发布时间及精度、累计/区间口径、原始指标名与数值、来源页面、截图/报表证据路径或飞书链接、成功/部分成功/失败、缺失字段及原因。

统计截止未知时明确写“采集时刻所见，平台截止未知”；下载时间只能证明下载发生，不能冒充平台截止。日期粒度的发布时间不能当作准确时分。页面显示“万”等缩写时保留原样，不能伪造精确整数。

原始指标与派生指标分开；零、未提供、未采集区分。搜索来源占比和搜索词只在后台实际提供时记录。不同页面的统计范围分别保存，不混加总览、日表、小时表，也不根据截图变化补造评论或关注来源。

同账号复盘目录下保存原始快照与采集状态；已有“已发布笔记数据”等存储时先核实用途和账号，能复用则沿用。用户授权飞书归档时才按 lark-doc/lark-drive 写入，写后回读；上传失败保留本地证据与待归档状态，不重复抓取冒充新数据。仅归档与分析有关的后台数据，不扩大文档权限。

快照 ID 由账号、笔记、来源、统计窗口/截止及内容摘要生成；后台未提供截止时加入实际采集时间。重试同一次抓取复用 ID，已保存则不重复新增；统计口径相同但数值变化时保留新快照及关系。执行先检查目标是否已完成，写入并验证成功后才标完成，失败只更新错误状态。

## 时间窗口与补采

- 只有平台精确时间区间导出或可信截止恰好对应发布后 24/48 小时，才能标实测该窗口；例如 25 小时读到累计值，就标实际 25 小时快照。
- 近似窗口可以供参考，但在单篇“非标准窗口”中明确距离目标的偏差；总表标准列保留待采集/缺失，不通过线性折算补齐。
- 后台允许历史区间查询时检查粒度与边界后恢复；只有按日数据、而发布发生在日中时，不能宣称精确恢复首 24 小时。单次当前累计数据不能重建过去曲线。
- 7/30 天快照同样记录实际时间；同口径快照才可计算增量。最新累计可更新总表“最终数据”，在状态和单篇标明截至时间及仍在观察，最终列不表示永远不再变化。
- 先保留已有历史记录与局限，不静默改动用户原始数字或指定口径。

## 一次采集的验收

核验账号/笔记 → 读取实际后台数据 → 保存原始证据与时间 → 去重 → 写单篇及适用的总表单元格 → 回读 → 更新目标状态。外部权限、登录或页面变化阻塞时，留下具体失败状态并停止该路径；不发布、编辑笔记或发送评论来测试采集。
