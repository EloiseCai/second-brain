# 选题内部路由

Topic Generator 消费用户洞察；热点报告仅 radar_mode=on 时作为输入，自己负责选题相关的验证、问题整理、候选生成与第二轮定向验证；不调用 audience-report 整轮研究或 topic-radar 扫描。全流程的上游运行由 writing-router 负责。

第一轮T1—T5共同执行 [问题库覆盖与选题多样性](diversity.md)，实际覆盖、历史去重和候选差异均留在同一研究备注。

| 步骤 | 执行与输出 | critique / 放行 |
| --- | --- | --- |
| T0 恢复与入口 | 绑定账号、平台、载体、内容选题/产品验证选题、指定题/生成题及断点 | 读取真实状态，不把“继续”当新任务；目标不明只澄清该字段 |
| T1 读取资料 | 覆盖本轮范围完整问题索引、六维与场景摘要，再深读拟入选卡片的原话及来源；读取关键词；按雷达开关读取热点报告（off跳过）；读取已有选题、相关素材与复盘 | 记录覆盖范围、实际问题ID、深读位置及更新时间；不能只读首条或只写“读过”；资料缺失标明，不隐式启动Audience Report |
| T2 定向多渠道验证 | 围绕候选问题核对搜索/下拉词、可用数据、相关原帖、评论反馈、适用的同类产品证据；复用同轮有效证据，补查新鲜度/反证/缺口 | 每渠道记录完成范围及已完成/部分/不可访问；需求证据与答案依据分开；不是重复全人群洞察研究 |
| T3 问题整理与角度 | 按具体处境、任务、卡点去重，引用六维辅助比较；保留原始具体问题，形成实质有差异的角度 | 执行 research-core/references/scene-contract.md；假设与已验证分开；不得用宽泛分类替代场景 |
| T4 可扩写、筛选与排序 | 比较历史候选、已选题、草稿及发布题的新旧价值，再检查核心承诺、需回答的问题、可提供的方法/例子、证据及缺口，再按主文件标准筛选排序 | 不能仅靠重复结论撑文章；此处检查内容支撑，不提前锁定段落、页数、食物数去套后续对标 |
| T5 用户选题 | 交付有区别的候选及理由、具体场景、证据状态、材料缺口 | 选择后进入T6；不代替用户选择 |

未指定题时执行T0—T5，用户选择后执行T6—T7。指定题仍读取账号、报告和来源，但跳过第一轮候选生成，从T6第二轮开始。两种入口都调用同一个topic-generator，不再设content-research。

| 第二轮步骤 | 执行与放行 |
| --- | --- |
| T6 定向验证与参考选择 | 读取 [第二轮协议](second-round.md)。按本篇类型与主题共同选择同一组对标，自己完整阅读并拆解内容和呈现方式；调用content-collector定向采集，不调用pattern-extractor。验证具体问题、答案能否成立与展开，优先从库内找相近内容和已有分析；定向搜索补缺，记录反证。流量不能证明知识正确。按拟规划平台注明参考用途和缺口，不批量扩库。 |
| T7 文档交接 | 写入选题研究文档：具体场景、来源、验证结论、相近参考及分析位置、可用知识与例子、事实缺口；回读并critique后，按audience-report统一写入关口完成增量回写或确认无新增，再交content-planner。 |

单独选题任务交接后结束；完整写作流程继续策划。

每步在当前飞书选题研究记录维护：任务ID、步骤、输入引用与版本/时间、产物位置、逐项critique与修正、缺口、用户已确认事项、下一步。未完成或失败的检查不能标为通过，恢复时先读记录再继续。

两种目标：内容选题以用户价值为先，产品相关性参与排序，无产品帮助不能单独淘汰有用内容；产品验证选题必须解释产品的实质帮助，允许清楚标识的新功能假设。目的在T0明确，不因某题热度高而偷换目标。

第一轮候选交付前及第二轮T7交接前，执行 [audience-report统一写入关口](../../audience-report/references/writeback-gate.md)。有新用户证据当场调用增量回写，读取最新字段与分析规则，写入回读成功后交接；无新增记录后继续。独立选题任务同样执行，不等待用户另行安排，也不为回写重跑全量研究。雷达关闭时热点报告缺失/过期不算缺口，也不触发扫描；仅雷达开启时向调度器报告热点资料缺口，独立选题任务可继续验证常青题，不能声称执行过雷达。
