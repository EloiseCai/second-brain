# 图片文案、发布正文与出图提示词：至少三轮复核

本协议是上述三种产物各自的内部放行条件，由 image-copy-writer、body-writer、cover-generator、image-generator 共用。继承 stage-critique.md 的逐模块检查及通用、平台、主题规则；不另加用户逐轮审批。三种产物分别完成三轮，不能用文案一轮、提示词一轮、成图一轮相加抵数，也不能把一次检查改名为三轮。

## 图片两次看对标的顺序

1. **写前看信息容量与整体组织。** 实际读完原图和已存整组分析，先确定本页的核心阅读任务、各区域作用、独立条目数量、文字篇幅、图文关系和大致排布，再按这些位置查证选材、拟写文案。此时即可发现错误比较对象或不适配的结构；“粗看”不代表只看缩略图、标题或忽略原文。容量依据及实际字数对照统一执行 image-generator/references/acceptance.md。
2. **文案拟好后，出图前细看。** 重开对应原图，逐区把最终文案落到实际布局：阅读顺序、重点大小、句长与换行、文字块位置、图文占比、标签指向、留白及装饰用途。依照原图结构细致模仿，配色、字体等沿用账号风格。把这份对应关系写入提示词，再执行提示词自己的三轮复核。不能只交一段文案让生成工具重新设计。

通用封面模式仍先做A/B各自首张内容页，用户选定后继承该套唯一整组对标并展开剩余文案；本协议不提前写两套全文、不重新选模。公众号仍先正文后配图，图片阶段执行这两次查看。

## 各模块使用自己的完整清单，每轮检查同样的全部项目

三个模块的检查内容分别制定。同一模块内部连续执行至少三轮，每轮都从头到尾检查该模块的同一份完整清单：第一轮全项检查并修正 → 第二轮对修订稿再次全项检查并修正 → 第三轮对最新稿再次全项检查并修正。不能把结构、事实、表达分摊到不同轮次，也不能后两轮只复查上一轮发现的问题。三轮的目的，是再次查找遗漏、完善细节和发现修改引入的新问题。

| 模块 | 每一轮都必须完整核对的内容 |
| --- | --- |
| 图片文本 image-copy-writer | 逐区对照原图的阅读任务、对象、信息关系、条目数量、文本容量和主次；逐句核对事实、单位、条件、比较对象、依据及新增假设；逐句检查清楚、有用、简洁有力、读者知道怎么做；核对标题与内容、插图指向、跨页推进、重复和单页负担，保持原图层级与留白容量，不擅增信息块、不缩字号塞字。执行本模块引用的通用、平台、主题及标题检查全项。 |
| 发布正文 body-writer | 按 sentence-alignment.md 完整双向逐句核对主对标，检查完整单元、语气、节奏、推进及写前钩子的引入和兑现；逐句核对知识、真实场景、因果、例子、适用条件和产品能力依据；全文逐句检查清楚、有信息、表达简洁有力、读者知道怎么做；连读核对衔接、主线、与图片互补及结论一致、重复和负担，保留有效例子与语言节奏；按启用状态检查产品、互动及当前平台/主题的全部适用要求。 |
| 出图提示词 cover-generator / image-generator | 逐区对照对应原图、获批文字及页映射（通用封面对照品牌标准），核对文字与版本、数量、位置、阅读顺序、主次、图文比例、留白和标签指向；检查比较符号、箭头及视觉关系是否改变事实含义，参考图旧文字是否干扰本篇；完整通读最终提示词，核对品牌风格、平台尺寸、手机可读性、指令冲突、遗漏、擅加解释和缩图塞字要求。发现文案问题回文案阶段修正及确认，不能暗改获批文本。 |

表中是三个模块的检查范围索引，各模块已引用的详细检查规则继续全部执行，不以此表代替原清单。每轮组合相同的通用、平台、主题要求；不在第二或第三轮减少项目。证据没有变化可以引用同一来源，但必须重新核对最新产物，不能复制上一轮结论。

三轮均覆盖当前阶段全部待交付内容。模块写完仍立即检查；文案整组及正文全文完成后核对覆盖与前后关系，不能用局部通过代表整体通过。局部改稿以受影响模块及关联上下文为范围，三轮范围一致，保留用户认可的无关内容。三轮后仍有问题则继续修正并全项复核，直到最新版本没有未解决的阻断项；不因轮数够了而放行。

## 与对标结论冲突时，先复查对象与假设

1. 回读对标实际说法与上下文，明确它比较什么、在哪种真实场景、用什么单位和条件。例如整杯饮品、单位体积浓度和某一种配料不能互相替换。
2. 写清本稿结论所依赖的条件，逐项查有没有AI自行加上的假设、遗漏的配料/份量/场景，是否因此换了题。不能先下结论，再找限制条件替自己辩护。
3. 查证同一对象和适用范围；适用时结合可靠原理与可核对的实际案例交叉核验。证据支持对标就纠正本稿；对标确实错误则在原位置用相近篇幅准确表达；证据不足保留待核验并补查。不能默认AI正确，也不能仅因对标流量好就保留错误。

核验过程及完整证据放制作备注，读者可见文字只保留准确结论和必要的简短条件。比较关系的改变必须重新审文案及批准范围，不让科学解释挤占整页。

## 单页超量时的处理顺序

一张图围绕一个核心阅读任务，任务中可以有对标规定的多个食物、选项或例子；不把“一页一个信息量”理解成强制只留一个条目。信息量同时包括答案、关系与解释深度，字数相近不等于信息容量相同。

先删重复、旁支与未经要求的扩写，再合并表达、改为简洁有力的句子；必要条件、独立答案和对标规定条目不能压没。已有长稿也先回到原图容量重写，不能让长稿决定版式。压缩后重跑事实与表达检查。

仍放不下时，列清具体溢出信息和它的必要性：适合正文的补充放到同主题正文规划；确需独立图页的，提出拆到哪页、每页任务、与原组结构及数量的变化，在现有审批节点取得明确确认后执行。未经批准不挪入已有下一页、不增页、不缩图缩字。已批文字发生实质改变，重新审受影响文案，不能在生成提示词中暗改。

## 留痕与放行

在当前飞书制作备注沿用一份记录：`产物/页码及版本｜轮次｜核对的原句或区域与来源｜具体差异或通过依据｜已改内容｜复查结果`。记录可简短，但三轮分别记录当轮检查的输入版本、修正后的版本及完整清单的覆盖结果，按顺序可追溯到最终版本；发现问题给出实际改句，没问题给出具体核对依据，不为凑轮次编造问题、不抄三遍“通过”，不输出冗长思考过程。

平台 writer 交接前回读三轮记录、最终文案/提示词及既有用户批准。缺轮、任一轮漏项、最终版本未完成全项复查、待核验或退回项未解决，均不放行。提示词三轮必须发生在调用生成工具之前。脚本结构校验不证明三轮实际执行或画面合格。

生成后继续执行 acceptance.md 的逐张原图/成图并排验收，不能用提示词三轮代替看图；发现失败回到对应文案或提示词修正并重审。

## 本次失误回放

- 对标比较实际购买的整杯饮品，本稿擅加“浓缩量相同”改成等号：每一轮均应在比较对象和新增假设检查处退回；提示词每轮同样核对比较符号，不能靠缩短文字掩盖语义变化。
- 原图短对比，本稿多出逐杯解释及两段说明：每一轮均检查容量对应，发现后精简回原有任务并重新全项核对，提示词不允许以缩图塞字实现。
- 第一轮只检查结构、第二轮只检查事实、第三轮只检查表达：三轮均未完成本模块完整清单，不放行。
- 文案记录三轮，提示词只读一遍；或出图后补写三轮通过：提示词阶段未完成，不能追认生成前验收。

以上是规则判定用例，不代表已完成真实生成测试或能保证模型永不漏执行。
