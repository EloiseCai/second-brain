# 断点恢复与阶段交接

先执行[逐条制作协议](../../writing-router/references/serial-production.md)，从内容包队列恢复唯一当前稿及其独立文档、Brief和当前模块。该稿未制作完成时只续做它；用户明确换稿则保存暂停断点和切换记录。

每次“继续”、选方案、局部修改或生成请求，先执行本页。公众号按 wechat-writer 的 WX1—WX8 顺序恢复，正文先行；下文 G 节点、整组图片先行及封面检查只用于相应图文/出图阶段，不能阻断公众号正文。不同平台各自使用独立飞书文档。先记录平台分支；小红书沿用既有阶段，并在 L Hashtag 后增加 L2 置顶评论，公众号使用 wechat-writer 的完整阶段，并对应 writing-workflow.md 总图。规则已确认、文章已完成、用户已批准分别记录。

## 唯一进度记录

漫画分支优先执行 [首页即封面的情景建立规则](../../story-builder/references/comic-storyboard.md)：P01为故事封面，不生成通用封面或套用其P02比较流程。记录首页情景是否完整、图文孕期身份是否一致及本批授权。用户直接要求按展示修订生成，沿用该授权，不重复请求同一批准；未选整组不推定为已选。下文通用封面条目仅适用于该形式。

由 agent 在当前飞书创作文档的制作备注维护一份“执行状态”，不要求用户填写，不新建本地文档。保留正文、原分析与获批文本各自唯一来源，仅记录引用：

- 文章及账号；本轮请求；工作节点；本轮具体交付物；下一步及其既有停顿点。
- 已完成研究：所属平台、证据包位置、用户确认范围。同平台写作阶段沿用，不因续聊重新产生“本轮至少新增1篇”的计数任务。
- 对标方案登记：A、B各自独立笔记ID、库内链接、真实首页与整组分析位置、读取版本、结构映射位置、当前阶段文字位置、critique结果；选择前只需样张文字，选择后补齐所选整组。
- 审批：用户原话/消息位置、批准的方案/页码/文本版本；未获批准的内容明确留空。
- 封面产物清单：每项分别记录用途（通用品牌/对标结构）、所属A或B、文案版本、参考来源、生成/实图验收/归档状态。通用品牌规范只引用主题包，不充当对标笔记。
- 知识图文的封面选择：记录 `cover_mode=brand/benchmark` 及用户原话。明确不使用通用封面时为benchmark，A/B各自原帖P01进入候选，选定后仅生成该篇P02至末页；纯标题P01也不删除。brand才执行首页去重与A/B成稿P02比较样张。续做时沿用已确认选择，不因当前稿已有通用封面标准而自动改回brand。
- 通用封面选模：单独记录封面批准状态、A/B第二页样张的文案版本、原图到成稿P02映射、实图位置、critique与实际展示状态；记录selected_scheme及用户明确选择原话。只确认通用封面不能填入selected_scheme；缺选择时停在比较节点，已有明确选择则沿用。
- L2置顶评论：独立于正文评论钩子，记录评论对标链接、逐句分析版本、草稿与critique、产品批准状态；完成后进入M验收。
- 当前缺口：精确到材料或映射项；已有但未读取、已读取但未登记、实际缺失分开记录。另记已生成文件，不能用文件存在反推阶段通过。
- 正文交接：当前正文版本、主对标原文链接、同版本逐句对照章节、双向覆盖与未解决句ID、逐模块风格及整篇推进结论。按 [body-writer验收](../../body-writer/references/sentence-alignment.md) 实际回读；缺记录/版本不符为待核验，存在偏移退回修改，不沿用“已参考”的口头结论继续下游。

## 续做顺序

1. 通读当前飞书稿和执行状态，核对用户最近指令及仍有效的此前批准；状态缺失时从现存文档、素材和用户记录恢复，不能仅凭聊天摘要猜进度，也不让用户重答已确认问题。
2. 先恢复已有研究与来源映射，再判断缺口。材料在库但未选为A/B属于G节点的选择/适配工作；有分析未读则读取；分析缺项交pattern-extractor原位补齐；原始材料缺失才交content-collector定向补齐。以上适用于同平台续做，不自动重启D节点研究；切换公众号则从公众号调研进入完整分支。
3. 两篇对标优先从当前账号已有证据包和素材库筛选，完整查看真实首页及整组图片分析。结构适配看信息作用与容量，原帖不必同题。不能把A的“7天/某菜/某布局”自动当成B的筛选前提；仅用户已确认的题意与承诺约束两套。
4. 检查本轮交付物属于哪个节点、前置材料是否实际存在、批准是否覆盖它。用户说“生成通用封面和对标封面”不会取消两篇独立对标；“继续”也不会补出不存在的B或批准未展示的文字。用户只批准A样张文字只能生成A样张，不得推定已选A整组；用户明确选定A后只展开A，B不再是生产前置条件。
5. 执行仅推进当前授权模块。缺项保留已完成研究和无关已批内容，只修复最早失效的依赖；用户要求查流程时只查改流程，不趁机补搜、出图或写正文。
6. 本轮取得新用户证据或纠正时，交接前执行 [audience-report统一写入关口](../../audience-report/references/writeback-gate.md)，使用最新规则增量写入并回读；无新增记录后继续。每个停顿、失败或交付前，回写并回读同一执行状态。说明“当前节点、已完成、本次缺项、下一动作”；不能将工具暂不可用写成研究未做，也不能仅因生成两张图就标两套完成。

## 两个维度分别计数

- **内容方案A/B**：来自两篇独立完整笔记，各有完整来源和整组信息需求；通用封面选模前各写首张内容页，选择后仅所选组补齐完整文本。同一笔记两张图、同一内容两种配色、通用封面加一张对标封面都只对应一个结构来源。
- **封面形式**：通用品牌形式与对标结构形式。每张均绑定实际方案，用户本轮要求决定生成清单。封面形式的数量不能抵扣对标方案数量，也不自动要求每套都生成所有形式。
- 对标结构封面核对原帖真实首页；使用品牌封面时按image-copy-writer首页去重规则。两种形式的存在不授权覆盖已选形式或改变内页顺序。原帖首页承诺与全组必须读，品牌模板的固定视觉单独引用。

## 出图前可执行检查

小红书每批内页（含A/B第二页样张）另须执行 [内页检查](interior-gate.md) 及 `scripts/check-interior-handoff.py`。封面检查通过不能放行内页；必须核对真实用户选模证据、整组唯一来源、原图继承清单与本篇逐页规划。

cover-generator 调用生成工具前，从刚回读的执行状态导出临时JSON，通过 `scripts/check-cover-handoff.py`；输入与结果留在飞书制作备注，临时文件置于系统临时目录。字段见脚本。检查的是来源身份、交付绑定和批准范围，不代替阅读原图、营养核验或文案critique；不能为了通过而填未经验证的true。未通过先按报告修复登记或实际缺项。

只有用户明确批准单套继续时，才在 `single_scheme_approval` 写入可定位原话；普通“可以”“继续”“生成封面”不能当单套豁免。检查脚本无法证明引用真实有效，agent须实际核对；这是执行前检查，尚未成为平台层面对工具的强制拦截。

## 断点回放（流程判定，不代表成图质量测试）

| 现有证据与请求 | 恢复后的动作 |
| --- | --- |
| 研究已确认；A/B未登记；用户说继续 | 读证据包和素材分析，恢复G；先库内选两组，不重跑研究 |
| A已有完整内容；通用品牌图与A对标图已生成 | 来源仍只有A；不得将两张计成A/B |
| A/B齐全、对应文字均批准；用户说生成封面 | 按已确认产物清单直接生成，不重新调研或重复审批 |
| 原图与分析已在库，只是当前会话未读取 | 读取对应原文；不称“缺对标”或要求重新入库 |
| 通用封面已批准；A/B整组未选 | 按已批文案补齐并展示A/B第二页样张和来源，请用户选定整组后补齐所选剩余文案，获批再生成内页 |
| 用户只改高亮/字体 | 在已批方案中局部改图，A/B身份及研究状态不变 |
| 用户要求检查流程 | 保持文章暂停，修规则与当前进度描述，不继续内容生产 |
