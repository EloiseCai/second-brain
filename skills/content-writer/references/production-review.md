# 图文生产与交付验收

本文件与 [逐环节 critique](stage-critique.md) 配套执行。整组规划完成、每轮提示词定稿、每轮实际成图均分别自检；生成前先确认主题语义完整，生成后先检查实际阅读含义，再检查下列设计细节。不能仅在正文完成后统一检查。

## 先筛适配，再生成候选

先核对已确认题意、具体角度与 topic-generator 证据包，再实际读取候选整组在飞书已保存的逐页及整组图片分析，并与原图核对。执行 image-copy-writer 的前置门槛：选定整组 → 引用逐页任务、关系和数量 → 按信息需求查证选材 → 写实际内容 → 核对标题与正文分工。旧稿和既有菜品不能作为选择容量的限制；评论仅补充已确认主线。用户明确保留的内容按其批准范围处理。

先明确主题、核心问题与内容边界，再选择整组图片模板。模板主要按能否承载本篇内容判断，检查页面功能、信息容量、食物/例子数量与解释空间；不要求原帖主题、营养素或具体问题完全相同。菜品合集与餐次搭配均可转化为补钙内容，先做实际映射再判断，不以原帖没有补钙主线直接排除。

先评估两篇整组模板候选，按下方“两套内容方案验收”分别完成整组实际文案；依据来自飞书已保存的[整组图片内容分析](../../content-collector/references/image-content-analysis.md)。可调整本篇表达方式，不能为填格而凑内容。模板与内容方向确定后，调用 [title-writer](../../title-writer/SKILL.md)，按主 Skill 的发布标题参数拟3个候选供选择；标题选定并通过 [Brief 图片文案审批](brief-approval.md) 后才生成封面候选。不足两篇时继续查找已授权素材，仍不足则展示合格方案并说明具体容量缺口，不凑数，也不能把单套报告成“两套完成”。

每个A/B候选单位是一篇完整笔记，身份与封面形式按 [断点恢复协议](resume-contract.md) 分别登记。对标结构封面实际查看并对应原帖真实首页，不能抽内页或同一篇两张图凑两套。账号统一品牌封面按已确认标准和image-copy-writer首页去重规则处理，不套用“必须照原帖封面排版”的旧要求；原帖首页及整组仍须读取并建立信息映射。选择优先复用既有研究与库内分析，只有实际材料缺失才定向补查。

用户选定封面，即确定该封面所属笔记为整组图片主对标。后续图片的内容组织、分组、例子展开、页面顺序、信息层级按该篇复刻，视觉按本篇已批准的账号方案执行；逐页映射只在这篇笔记的整组图片内进行，禁止每张另找一篇或混搭未选中的候选。其他资料可补充事实与具体内容，不承担另一套图片模板。用本篇有依据的内容改写，不照搬原文或未经核验的结论。

B类04的长文使用限制仍适用。B06《整个孕期补剂总结｜新手妈妈看这一篇就够了》（6a2384e00000000007010ade）已由用户删除并永久排除，历史缓存与草稿引用也不得重新作为对标。

## 两套内容方案验收（严格执行）

每套先执行 [图片文本写作的信息需求与数量硬门槛](../../image-copy-writer/SKILL.md#先确定原图信息需求再查证写作严格执行)。检查顺序为原图信息任务与容量 → 查证选材 → 实际文案 → 逐句及整组审查。整组页数、每页独立条目数量或提醒/推荐等页面任务与已选对标不符，且没有用户明确批准结构变更时，直接退回；不能用“已有内容只有这么多”“不凑内容”或普通措辞检查通过放行。换对标或用户要求重写后，旧文案必须重新验证，不作为固定输入。

两套是同一选题下分别适配两篇整组图片的 A/B 内容方案。共享核心问题、已确认承诺、事实依据与用户要求；页面分工、信息顺序和表达按各自真实对标适配。来源事实可共用，不能先按 A 写完一套文案，再仅替换 B 的封面和颜色。独立适配不要求为了不同而编造观点或刻意更换有效知识。

在同一飞书创作文档、唯一 AI 初稿内分别维护 A/B 两套，用户选择前两套均为有效候选，不能提前按“只留当前版本”清理掉其中一套。每套完整提供：

1. **引用依据**：完整对标路径、真实封面与内页位置、已保存的单图/整组分析及版本；只引用，不复制原分析。
2. **整组关系映射**：`原图页/标题/文本块/插图ID → 原信息类型与相互关系 → 本篇对应答案、事实依据与组织方式 → 读者新增收获`。明确承诺逐项落点、前后页衔接和图文分工。结构与容量应匹配；题意与事实决定可说什么，图片对标指导怎样组织，不能为填格凑内容或遗漏承诺。
3. **全部实际文案**：封面及每张拟用内页的标题、文本块、例子、必要条件和插图任务；不能只有“讲方法/讲选择”的任务名。不同角色的图片标题在文案阶段调用 `title-writer` 生成并逐条 critique，实际标题必须统领本页/本块的内容。
4. **独立验收**：本套逐项执行 [逐图读者收获与问题解决硬检查](stage-critique.md#逐图读者收获与问题解决硬检查)、[明确答案与认知负担检查](stage-critique.md#明确答案与认知负担检查) 和 `title-writer` 的对应角色 critique；记录实际问题与改动。A 通过不能代替 B，图文分析本身完整也不能替代本篇实际文案检查。

两套内容规划和图片文案在已授权的内容初稿阶段完成；两套 Image Brief 完成后，全部预设文本统一写在 Creative Brief 末尾，Image Brief 按页码引用，不维护重复正文。图片正文增强、产品说法复核与用户批准执行 [Brief 审查](brief-approval.md)，封面实图须等文案获批及标题选择。展示封面时同时提供各套内容展开与逐页文案的飞书位置，让用户清楚选择会决定哪套整组内容。用户选定后才生成该套内页，不默认提前生成两套全部实图，也不提前写发布正文。

若共用的已确认标题或承诺在一套中无法兑现，先修内容或重选该组对标，不能悄悄放宽标题。用户明确只改封面细节时在选定组内修；明确更换整组时回到该组内容映射，重做受影响的逐页文案、标题适配及 critique，已核实事实继续引用，不能直接沿用旧结构。

### 两套与标题的放行回放

以下是审查用例，不冒充真实素材或已完成的成图测试：

| 输入情形 | 必须判定 |
| --- | --- |
| 两张封面已生成，但 B 的内页只有任务名 | B 实际文案未完成，不可报告两套完成 |
| A 是因果解释，B 是步骤图，却完全共用 A 的文本且无 B 关系映射 | B 适配退回；排版和块数相同不能证明内容关系相同 |
| 两套引用相同事实，分别以有效比较与解释结构组织，均有完整文案及证据 | 独立核对后可通过，不为区别而换掉真实知识 |
| 内页标题写三个原因，下属三块实际是连续操作 | 标题与内容关系退回，修复后重审本页及相邻页 |
| 发布标题已审，图片标题只是临时加的栏目名且未调用标题规则 | 图片标题检查未完成，不进入出图 |
| 用户尚未选择，提前删去 B 以满足唯一版本 | 候选交付不完整；选择前两套均有效，选择后再按清理规则收敛 |

## 设计锁定与细节检查（生成前后都必须执行）

用户选定封面及所属主对标后，逐页复刻已存分析和原图的信息结构、任务、数量及关系，按 image-copy-writer 验收；结构变更须明确批准。视觉细节依账号及本篇已批准方案，不自动照搬对标全部色彩、字体、餐具、材质或装饰。事实核查不能成为擅改结构的理由；内容不足先补查并重新选材。

逐页建立“已存分析与原图 → 本篇结构要求及获批视觉 → 实际成图”的记录；下表用于逐区域核验，结构与信息关系必须对应，纯视觉细节按已批方案检查。原图不存在的内容不臆造，不为复刻视觉强行增加无关信息。

| 检查项 | 必须对应的细节 |
| --- | --- |
| 构图与容量 | 网格行列、格数、边界与分隔、各主体位置和大小、图文比例、裁切与留白 |
| 文字 | 实际文字块数量、行数、上下位置与间距、字号层级、字体粗细与倾斜、描边、底色或刷痕；原图无菜名标签、说明、脚注或角标时不得新增 |
| 餐具与道具 | 勺子、筷子、碗盘各自的种类、材质、颜色、形状、大小、可见部分、伸入方向与夹起/舀起动作；餐具是否一致按获批视觉执行，搭配与演示动作必须准确 |
| 视角与层次 | 俯拍或斜拍、取景距离、前景主体与背景的位置、遮挡、景深和虚实、碗沿露出程度；保留承担信息作用的差异，视觉按获批方案 |
| 食物与光色 | 本篇菜品对应的位置、分量呈现、形态与纹理、光照方向、高光、明暗和色彩差异；图中食物必须与后续内容对应 |
| 装饰 | 原图实际存在的刷痕、线条等的位置、面积与作用；按本篇获批视觉，不添加未经确认的装饰 |

将这些具体要求、已存分析引用和对应原图一起交给生成工具。生成后并排查看原图与实图的完整尺寸及缩略图：先核对结构、信息容量、图文关系与获批原文，再审本篇获批视觉细节。实际成图未落实就修正并更新提示词，不以提示词已写或整体相似放行。

005/B25的已确认纠错示例：原图三列三行、只有上下分开的两行大字，不得改成六格或添加菜名、底部说明；瓷勺、银色金属勺、金色金属勺、筷子及其方向和远近逐格对应。此例的餐具与视觉细节只适用于该篇已批准设计；其他篇按其分析结构与已批准视觉执行，不一律套九宫格或两行字。

## 品牌栏按需添加

只有用户明确要求图片增加品牌栏时才执行；未要求则不自行添加。正文产品承接与图片品牌栏分别判断，不能因需要产品曝光而跳过用户的启用条件。已确认的同篇要求延续到后续改图，不重复请求确认，也不扩展成其他笔记的默认设计。

- 先记录用户要求的页面范围、品牌名称、IP、色系与文案。用户要求从第二页开始时，逐一覆盖第二页至末页，封面不加；其他篇按各自明确范围执行，不能机械套用012。
- 用户提供示意图时，提取信息和视觉方向后重新美化，不整张直接贴入。使用正确的品牌IP及色系，以低矮单行、适当留白和清晰字号呈现，不挤占主要信息、不遮挡原文、不擅加独立页面；不把一次实现的像素高度定成永久规格。
- 提示词须包含品牌栏的范围、内容与版式要求。实际成图逐页核验品牌文案准确、IP一致、字号可读、占高适度、无遗漏或误加，之后同步飞书及项目内最终文件。

## 选定模板后再校准信息量

### 已选对标的数量与信息价值共同验收（硬规则）

已选整组对标时，先按原图列出逐页任务、条目数量与解释需求，再查证选材和写作；执行 `image-copy-writer` 的信息需求与数量硬门槛。页数、食物/例子数量和页面功能按对标对应，不能先写少量内容再自行缩页。数量达标与独立信息价值必须同时满足。不为产品曝光、重复总结或无效警示额外增页；所需产品承接优先安排在正文。仅当用户明确授权自由规划或改变已选结构时，才按批准范围重新分配页数。

每张内页交付服务本篇承诺的独立阅读价值。知识页提供答案、解释或例子；总结页把已展开的知识压成容易记住和使用的原则，按[借鉴 critique](../../content-collector/references/image-content-analysis.md#借鉴-critique严格执行)判断其作用，不因没有新事实就删去。出现换词重述、泛泛警示或自我免责时，先重写该信息单元或补充有据选材；不能以去重为由静默删除已选对标的页或条目。只有用户明确授权调整结构后才合并删页，并说明内容落点。

生成前执行[逐句信息价值与凑页硬检查](stage-critique.md#逐句信息价值与凑页硬检查)。没有通过实际文案检查，禁止出图；图像尺寸、设计、来源齐全均不能抵消文案无价值。生成后对实际图中文字重做同一检查。

### 内容完成后主动 critique，再进入出图

每次完成内容规划、图片生成或正文改稿，都由 AI 主动执行“检查具体问题 → 修改 → 复查”，不等用户指出，不以道歉或列出下一步代替修改。制作备注只记录实际发现的问题、落实到哪一格/哪一段的修改和复查结果，不虚构缺点或机械凑检查条数。

生成封面前，先写完整组每一格的实际内容、对应原图、该格新增的阅读价值及图文分工。内页只写“讲计算”“讲搭配”等任务名、实际菜品和例子仍未准备好时，不能先生成封面交差。先检查内容是否足够且有用，再检查排版、尺寸与美观。

标题中的“3步”等数量是必须兑现的承诺，不是全文只能容纳三条提示的上限。食谱与方法结合的主题，应提供足够具体的餐食选择、相关营养解释和实际示范，让步骤在餐食例子中自然发生；不得把同一餐盘重复多个格子，分别贴“看标签、称重量、相加”等口号充数。已明确采用的评论可作为问题入口；用户允许扩展时，可增加服务同一问题的餐食与场景，但不能伪造为评论者原话或经历。

逐页检查：遮住菜名后是否仍有实质差别？每格是否增加一种有用选择或知识？读者能否沿完整例子实际完成标题承诺？数值是否有依据，算例是否从输入、单位、换算到结果完整？营养解释是否被流程口号挤掉？对标若用餐盘提供多样搭配，应保留这种内容价值；不只复制网格外形。解释可按对标容量放在正文，图文共同兑现承诺，但必须明确哪些信息只在正文，不能宣称图片已教会全部步骤。

发现核心答案或已选对标需要的有效信息不足，补齐相关素材、有效餐食或完整示范；发现重复，重新选材或改写，确保每项有用。确实无法补齐时报告具体缺口，未经确认不缩减结构。发现数值缺证据，核实或明确改为假设算例。不能靠增加页数、小字、装饰或用户事后纠错弥补。被用户否定的图片退出有效候选；替代图交付验证后删除废弃生成文件及对应飞书图片块。问题只在当前制作备注简记，不保留废图作为问题记录。

每个候选生成封面前先做一次校准；用户选定后，对整组内容页再次校准。逐页记录：原图每区的任务、条目数、约字数/行数、例子或食物数、图文比例；本文对应区的实际文字与条目数。以原图容量规划本文有用的解释、例子、动作和必要条件，但不能为填满画面添加无关知识、重复内容或未经证实的结论。

信息多时先删重复，把补充解释放正文，保留选定原图的文字层级、网格与图片数量；信息少时不能自行删格、改图文比例或填入无关内容。整组仍不适配时明确说明具体内容缺口后再调整方案，不暗中改动已认可设计、不跨笔记另找模板，也不把封面版式重复铺满内页。不要通过极小字号、异常留白或自创布局勉强容纳。整组页数及逐页条目数按所选对标分析继承，未经明确批准不改变；不预设所有文章8张；产品承接优先放正文，只有对应原图存在适合的区域或用户明确要求时才上图，不另加底部小字。

生成前须保存整组覆盖表：原帖每页任务 → 本篇对应页与具体条目 → 新增答案 → 重合信息 → 省略理由或正文分工。按[逐环节 critique](stage-critique.md)的硬性退回条件检查。不得将“16格都填了”“主题聚焦”“原图本来重复结构”作为内容充分的证据；结构可以重复，读者获得的答案须推进。原帖7页与本篇2页这样的收缩，若没有明确结构变更批准直接退回；有批准仍须核实是否遗漏核心问题和实际内容深度；有缺口就补内容，不先宣布整组完成。选择完成后删除未选生成方案与失效计划，只维护当前有效图片清单；来源保留链接，不复制未选整组到交付目录。

## 成稿清理与唯一版本验收

## 每页交付

正式生成前建立并保留[整组交付清单](stage-critique.md#整组完成判定先锁定范围再核对实物)，每页更新实际状态。完成全部单页验收后，另做一次整组交付核对：用户要求 → 清单 → 当前有效文件 → 指定交付位置逐项一致。批量工具失败或缺图必须处理，不以成功返回的部分图代替整组，不因局部检查通过提前结束任务。

- 上图原文：所有实际显示的文字，逐区写全，不混入“核对、不得出现”等制作指令。
- 制作说明：选定主对标的笔记标题、具体原图路径/编号、该页在整组中的阅读任务、内容改写、排版与风格、区域容量，以及上表逐区域/逐格的细节对应记录。所有页面须归属同一主对标。
- 实际提示词：保留传给 imagegen/image2 的完整文本、参考图片路径和尺寸要求；修改图片后同步当前提示词。
- 验收：主对标是否与选定封面一致、后续内容是否参考该篇的整组推进、是否跨笔记拼模板、是否偏离本篇问题，以及实际尺寸、完整非透明背景、文字无截断。逐项确认设计未擅改、无额外小字、餐具与视角等细节已落到实际成图；保留具体核验记录。统一配色不能代替整组内容连贯，提示词存在不等于生成图已通过。

## 文案与承诺验收

正文外层按 body-writer 的“正文内容 → 产品承接 → 评论钩子”验收；内部按已选正文对标逐句借鉴语气和文本结构，并说明如何补充图片。采用导读时须点名具体阅读收获并兑现，删除空泛预告；不强制每篇都有独立总体方案、导读或固定数量模块。

检查疏密与扫读：按选定正文对标的语气、句式和段落组织承载本篇内容，使用具体菜品组合、简短小标题、关键句或必要的重点标记帮助扫读，段落自然说明做法、理由及替换条件，扫读能抓住安排，关键词行仅为可选。细读能理解营养理由与选择方法，不能每篇固定成“餐名＋关键词＋营养解释”。内容可以不同，写作方式须有可定位的原段与本稿对应证据；按stage-critique中的正文风格项独立验收。导读用自然语句概括方案，不把多个带引号的完整问题拼成目录句；不能把“易读”误解为全文越短越好。

正文每个模块均须有独立来源映射：对标原文/图片文字及具体位置 → 借鉴写法 → 对应规律 → 本文具体落点 → 支持事实的已读资料。开头、总结、CTA同样检查。只列素材编号或一组资料链接不算逐项对应；原创组织如实标注，不虚构参考原文。

逐项对照标题承诺和真实提问，定位图片页及正文答案。例如“按阶段整理”须清楚交付各阶段的重点与行动，不能只按营养素列名单；“看是否缺乏”如果未给出可用判断信息，就是尚未回答的选择问题，应补足有依据的答案或收窄承诺。

逐段逐页问：这部分如何兑现本篇核心承诺，读者因此知道怎么选、怎么做了吗？选用的评论副问题是否在合适位置得到回应？只有主题关键词相同、菜品介绍完整或对标设计相似不算通过。正文可选择必要的图片例子，不要求按图片顺序复述全部菜品；图片先行的生产顺序不改变用户痛点优先的内容逻辑。

最后检查实际交付：用户能采取什么动作、为何这样做、哪些问题仍留给读者；有无重复空话；原文映射是否完整；提示词是否已存；正文中的明确产品承接是否存在，并通过 stage-critique 的产品承接独立检查（存在性、主题价值、功能证据、衔接表达、独立写法对标）；缺失或仅泛泛提到产品即退回修改；评论钩子是否存在（不要求固定求赞）；“推荐 Hashtag”是否恰好有 10 个不重复且与本篇贴合的标签，制作备注能否追溯同主题对标原标签、出现篇数、筛选及补充来源；当前只有一版AI初稿。以可定位的文本和图片作为通过依据，不以章节齐全或校验脚本通过代替质量判断。
